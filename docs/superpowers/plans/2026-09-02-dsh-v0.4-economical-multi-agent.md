# DSH v0.4 Economical Multi-Agent Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a keyless, bounded, Orchestrator-internal parallel Task DAG runtime with declaration-layer ownership enforcement, deterministic aggregation, integrated verification, strict durable replay, and no physical workspace isolation claim.

**Architecture:** `@han_05/dsh-scheduling-contracts` remains a pure no-Cordis package and becomes the authority for parallel constants, repository path/identifier grammar, structural DAG and verification-policy parsing, aggregate types, aggregate parsing, and serialized-payload measurement. `@han_05/dsh-orchestrator` owns semantic DAG validation, deployment∩node scheduling constraints, atomic fan-out admission, strict legacy/parallel event unions, raw Handoff ownership classification, deterministic aggregate construction, leaf-worker execution, integrated verification, and the generation-safe `parallelExecution` service; only a test-only Loader overlay over `profiles/v0.3-adaptive` activates that service.

**Tech Stack:** TypeScript ESM, Node.js 24, pnpm 11.7.0, Vitest 4.0.18, TypeScript 5.9.3, exact DeepSeek Harness `0.1.1-rc.2`, `@deepseek-ai/cordis@4.0.1`, DSH Session/Subagent/Subprocess services, SHA-256 from `node:crypto`, and real Loader composition through `@deepseek-ai/dsh-app-boot@0.1.1-rc.2`.

**Spec:** `docs/superpowers/specs/2026-09-02-dsh-v0.4-economical-multi-agent-design.md`

## Global Constraints

- Keep DeepSeek Harness pinned at `0.1.1-rc.2` until a separate compatibility review proves an upgrade.
- Preserve Direct mode, Single Worker mode, `HandoffV1`, plugin-owned budgets, targeted verification, canonical `dsh-plugin/` events, and the keyless `DISABLED` provider smoke (`pnpm test:provider` always prints the exact `DISABLED` line).
- The Orchestrator owns task DAG, independence/ownership validation, worker lifecycle, final budget admission, Handoff normalization/aggregation, and event recording. The Scheduler only provides capability-to-schedule decisions.
- Do not fork or modify `upstream/deepseek-harness` or replace its agent loop.
- All model-visible outputs and orchestration evidence stay bounded, provenance-carrying, and safe to replay. Arbitrary-length Harness child Session IDs never enter v0.4 parallel durable payloads; the byte-compatible legacy non-parallel `worker-finished` shape is the only exception.
- No orchestration decision may bypass `maxWorkers`, `maxPluginToolActions`, tool allowlists, workspace/verification policy, or disjoint ownership.
- Workers use the shared working tree and self-report `changedFiles`. v0.4 enforces only declaration-layer containment against `writePaths`; it does not claim physical containment, trusted write capture, diff containment, or transactional integration.
- Per-node `TaskNodeV1.constraints` may only narrow deployment limits. Every field uses the spec's deterministic intersection rule; required capabilities fail closed when the intersection is empty.
- Unknown quota, price, and health values are never invented or silently estimated into hard routing decisions.
- Add no v0.4 Profile and do not change `profiles/v0.1` or `profiles/v0.3-adaptive`. Activation is only through a loader-convention-compatible test overlay over `profiles/v0.3-adaptive`.
- Keep `subagentMaxDepth: 1`; every parallel child is fresh, foreground, and unable to delegate recursively. Parallel workers never receive `targeted_verify`.
- Preserve existing public `parseHandoff`, `normalizeWorkerOutput`, Direct, Single Worker, `BudgetController` scalar-admission, and `run-started` actual-route semantics.
- Physical workspace isolation and all v0.4a seams (`prepare`, trusted `diff`, transactional `integrate`, per-child cwd/fs roots) are deferred and must not appear in implementation tasks.
- No task may access providers, credentials, paid endpoints, network endpoints, raw transcripts, authorization values, or provider-owned quota/cost endpoints.
- “Reload-safe” means same-process service-generation/HMR reload over a live Session. Process-restart/crash durability is outside this plan.
- Every implementation task starts with a failing focused test, records the expected RED reason, implements the smallest GREEN slice, runs the listed targeted regressions and typecheck, inspects its diff, and commits only the task's scoped files.

  ```ts
  // packages/dsh-scheduling-contracts/src/parallel-paths.ts
  const NODE_ID_PATTERN = /^[^\u0000-\u001F\u007F\u003A\u0022\u005C]+$/u
  const GLOB_PATTERN = /[*?\[\]{}]/u

  export function isWellFormedUnicode(value: string): boolean {
    return value.isWellFormed()
  }

  export function parseNodeId(value: unknown, path = 'nodeId'): string {
    if (typeof value !== 'string' || value.length === 0 || !value.isWellFormed() || !NODE_ID_PATTERN.test(value)) {
      throw new TypeError(`${path} does not match the nodeId grammar`)
    }
    if (utf8ByteLength(value) > 32) throw new TypeError(`${path} must not exceed 32 UTF-8 bytes`)
    return value
  }

  export function parseRepoFilePath(value: unknown, path = 'path'): RepoFilePath {
    const parsed = parseRepoPathDeclaration(value, path)
    if (parsed.endsWith('/')) throw new TypeError(`${path} must name a file`)
    return parsed as RepoFilePath
  }

  export function repoPathContains(owner: RepoPathDeclaration, file: RepoFilePath): boolean {
    return owner.endsWith('/') ? file.startsWith(owner) : owner === file
  }
  ```

  ```ts
  export function deriveAggregateStatus(results: readonly ParallelNodeResultV1[], verification: VerificationOutcomeV1): ParallelAggregateV1['aggregateStatus'] {
    if (results.some(result => result.status === 'failed')) return 'failed'
    if (results.some(result => result.status === 'ownership-violation' || result.status === 'blocked' || result.status === 'not-run')) return 'blocked'
    if (verification === 'admission-rejected') return 'failed'
    if (verification === 'command-failed') return 'verification-failed'
    if (verification === 'not-run-no-accepted-nodes' || results.length === 0) return 'blocked'
    return 'completed'
  }
  ```

  ```ts
  export async function runParallelVerification(options: ParallelVerificationRunnerOptions, acceptedNodeCount: number): Promise<ParallelVerificationResultV1> {
    if (options.policy.commands.length === 0) return { outcome: 'not-run-no-commands', evidence: [] }
    if (acceptedNodeCount === 0) return { outcome: 'not-run-no-accepted-nodes', evidence: [] }
    const evidence: VerificationEvidenceV1[] = []
    for (const command of options.policy.commands) {
      const admission = options.controller.admitPluginTool('targeted_verify')
      if (!admission.allowed) return { outcome: 'admission-rejected', evidence }
      const item = await options.service.run(command.name, command.args, options.signal)
      evidence.push(item)
      if (item.status !== 'passed') return { outcome: 'command-failed', evidence }
    }
    return { outcome: 'passed', evidence }
  }
  ```

  ```ts
  export function mountParallelExecutionService(ctx: Context, options: ParallelRuntimeOptions) {
    const generation = new AbortController()
    const active = new Set<Promise<unknown>>()
    let disposing = false
    const runtime = createParallelExecutionRuntime({ ...options, generationSignal: generation.signal })
    const service: ParallelExecutionService = {
      run(request) {
        if (disposing) return Promise.reject(new ParallelGenerationDisposedError())
        const promise = runtime.run(request)
        active.add(promise)
        void promise.finally(() => active.delete(promise))
        return promise
      },
    }
    const unregister = ctx.provide('parallelExecution', service)
    return { service, async dispose() { disposing = true; generation.abort(GENERATION_DISPOSED_REASON); await Promise.allSettled([...active]); unregister() } }
  }
  ```

```text
1 paths/bounds
  -> 2 DAG + verification policy
  -> 3 aggregate contract/parser
  -> 4 semantic DAG validation
  -> 5 config + atomic fanout budget
  -> 6 deployment∩node scheduling
  -> 7 durable event unions
  -> 8 raw Handoff ownership
  -> 9 aggregate builder
  -> 10 admitted leaf worker
  -> 11 DAG runtime
  -> 12 integrated verification/fold
  -> 13 generation-safe activation
  -> 14 replay + Loader overlay + gate
```

No implementation tasks should run concurrently. In particular, do not parallelize Tasks 5-7 (shared config/scheduling/event contracts), Tasks 8-10 (the raw-Handoff/event-size ordering is normative), or Tasks 11-13 (runtime commit and disposal semantics are sequentially defined).
