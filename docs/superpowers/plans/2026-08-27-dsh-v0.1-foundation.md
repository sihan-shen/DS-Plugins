# DSH v0.1 Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a runnable out-of-tree DeepSeek Harness plugin that supports Direct and one-shot Single Worker coding flows, returns a bounded versioned handoff, enforces deterministic limits, and records targeted verification evidence.

**Architecture:** A repository-local profile bundle composes Harness `0.1.1-rc.2` and one `@han_05/dsh-orchestrator` Cordis function plugin. The plugin contributes prompt sections and two bounded tools: Single Worker mode exposes `delegate_worker`, while both modes expose `targeted_verify`; pure modules own contracts, validation, budget admission, handoff normalization, and verification evidence, and typed session events make every model-visible result reconstructable.

**Tech Stack:** TypeScript ESM, Node.js 24, pnpm 11, DeepSeek Harness/Cordis `0.1.1-rc.2`, Schemastery, Vitest, Harness Loader smoke and keyless LLM replay support, Nix development shell.

**Spec:** `docs/superpowers/specs/2026-08-27-dsh-v0.1-foundation-design.md`

## Global Constraints

- Pin DeepSeek Harness to commit `b150a551b8d465e31e418e1b2eaf5e79bbb7d28e`, version `0.1.1-rc.2`; do not silently move the pin.
- Extend documented Harness APIs; do not modify or fork `upstream/deepseek-harness` or its agent loop.
- Use the official `dsh-llm-pi-ai` `openai-codex` authorization and adapter path; do not implement OAuth or persist tokens.
- Install no community plugin in v0.1.
- Single Worker mode starts at most one one-shot child, uses maximum depth one, and never runs parent and child write-capable work concurrently.
- Every plugin-owned record uses `schemaVersion: 1`, JSON-only fields, bounded strings and arrays, and repository-relative paths that cannot escape the workspace.
- Execute verification programs directly through the Harness subprocess capability; never pass a shell string, redirection, command substitution, or arbitrary executable.
- Tests use real Loader composition and keyless replay for model-visible behavior; direct `ctx.plugin()` tests alone do not satisfy integration acceptance.
- Keep credentials, raw worker transcripts, unrestricted command output, and authorization values out of plugin events and Handoff data.
