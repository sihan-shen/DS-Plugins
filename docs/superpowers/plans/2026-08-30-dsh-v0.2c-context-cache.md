# DSH v0.2c Context Blocks and Bounded Cache Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement keyless v0.2c immutable context blocks, progressive source disclosure, a bounded persistent cache, and optional orchestrator integration without changing the v0.1 profile or provider boundary.

**Architecture:** `@ds-plugins/dsh-context` owns strict Context Block contracts and derived identity. A new `@ds-plugins/dsh-context-cache` package owns boundary-aware persistent storage, atomic single-writer commits, invalidation, eviction, and quarantine. `@ds-plugins/dsh-code-intelligence` compiles existing bounded Repo Map/Symbol Query projections and verified source windows into blocks; `@ds-plugins/dsh-orchestrator` consumes an optional compiler service only in a new v0.2c overlay.

**Tech Stack:** TypeScript ESM, Node.js 24, pnpm 11.7.0, Vitest 4.0.18, TypeScript 5.9.3, exact DSH `0.1.1-rc.2`, `@deepseek-ai/dsh-subprocess@0.1.1-rc.2`, and the existing `@dqbd/tiktoken@1.0.22` evaluation path.

**Spec:** `docs/superpowers/specs/2026-08-30-dsh-v0.2c-context-cache-design.md`

## Global Constraints

- Keep Harness pinned at `0.1.1-rc.2`; do not modify `upstream/deepseek-harness`.
- Keep `profiles/v0.1` behavior, Direct/Single Worker semantics, HandoffV1, five canonical events, and provider-disabled behavior unchanged.
- All model-visible values are bounded JSON-only projections with workspace, snapshot, adapter, policy, and source provenance.
- `parseContextBlockV1` recomputes `contentHash`, UTF-8 `byteLength`, and `blockId`; forged or unknown fields fail closed.
- Cache storage is only `.dsh-context-cache/v1/` under the trusted deployment root, mode `0700` where supported, with no credentials, transcripts, diagnostics, or inherited environment values.
- Cache writes use a same-directory temporary file and atomic rename under a single-writer lock; lock timeout is a miss.
- Cache limits are exactly 10,000 entries or 256 MiB, and quarantine limits are exactly 32 files or 10 MiB.
- Revision is a lookup hint, not a global invalidation key; changed dependency hashes invalidate only affected entries, and incomplete dependency data misses closed.
- `.dsh-context` and `.dsh-context-cache` are hard snapshot exclusions before ignore traversal.
- Source expansion repeats deployment-root containment, regular-file, size, stat-signature, byte-length, and SHA-256 checks.
- No task may access providers, credentials, paid endpoints, network endpoints, raw transcripts, or write-capable tools.
- Every implementation task writes tests first, runs the intended RED test, implements the smallest GREEN change, runs its focused regression, and commits its own files.

**Interfaces:**
- Consumes: `ContextBlockV1`, `parseContextBlockV1`, `canonicalJson`, and `sha256Utf8` from `@ds-plugins/dsh-context`.
- Produces:

  ```ts
  type CacheBoundaryV1 = {
    workspaceFingerprint: string
    snapshotId: string
    adapterId: string
    adapterVersion: string
    compilerPolicyVersion: string
    capabilityVersion: string
  }
  type CacheLookupKeyV1 = CacheBoundaryV1 & { normalizedQuery: string; dependencyHashes: readonly string[] }
  type ContextCacheConfigV1 = { deploymentRoot: string; maxEntries?: number; maxBytes?: number; lockTimeoutMs?: number }
  class ContextCacheStore {
    static open(config: ContextCacheConfigV1): Promise<ContextCacheStore>
    getBlock(blockId: string, boundary: CacheBoundaryV1): Promise<ContextBlockV1 | undefined>
    putBlock(block: ContextBlockV1, boundary: CacheBoundaryV1): Promise<void>
    getToolResult(key: string, boundary: CacheBoundaryV1): Promise<unknown | undefined>
    putToolResult(key: string, boundary: CacheBoundaryV1, value: unknown, maxBytes: number): Promise<void>
    getLookup(key: CacheLookupKeyV1): Promise<readonly string[] | undefined>
    putLookup(key: CacheLookupKeyV1, blockIds: readonly string[]): Promise<void>
    invalidateBySourceHashes(hashes: readonly string[]): Promise<void>
    close(): Promise<void>
  }
  ```

- [ ] **Step 1: Write RED tests for layout, boundaries, and atomic writes.**

  Assert the cache is created below the canonical deployment root with mode `0700` where supported; a block round-trips only under the exact boundary; workspace/snapshot/adapter/policy/capability mismatches miss; bounded JSON tool results round-trip only under the exact boundary; oversized/non-JSON tool results are rejected; and a failed temporary write never leaves a partially readable final entry. Configurable test caps are accepted only when they are positive and no greater than the exact production maxima of 10,000 entries and 268,435,456 bytes; omitted caps use those maxima.

- [ ] **Step 2: Write RED tests for invalidation, eviction, corruption, quarantine, and concurrency.**

  Assert source-hash invalidation removes only dependent entries, revision-only changes do not flush unrelated entries, an incomplete dependency list causes a miss, the 10,000-entry/256 MiB caps evict oldest entries, malformed entries move to quarantine and are not returned, quarantine stays within 32 files/10 MiB, and two simultaneous writers leave one valid immutable entry.

- [ ] **Step 3: Run the cache RED suite.**

  Run `pnpm exec vitest run packages/dsh-context-cache/tests/cache.spec.ts --config vitest.config.ts`; it must fail because the package does not exist.

- [ ] **Step 4: Implement canonical keys and filesystem storage.**

  Canonicalize the root with `realpath`; use content-addressed JSON under `entries/`, canonical lookup records under `lookups/`, quarantine under `quarantine/`, and an exclusive lock file. Write temporary files in the target directory and rename atomically; validate every read with `parseContextBlockV1` and exact boundary/dependency matching; update LRU metadata only after a successful read.

- [ ] **Step 5: Implement invalidation and bounded maintenance.**

  Record source dependency hashes beside each entry, remove only affected lookup references, sort eviction by last-access then entry ID, quarantine malformed records before maintenance, and delete oldest quarantine files until both caps hold. Return misses for lock timeout or any malformed index.
