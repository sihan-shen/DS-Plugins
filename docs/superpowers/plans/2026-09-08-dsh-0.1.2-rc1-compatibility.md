# DSH 0.1.2-rc.1 Compatibility Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade DS-Plugins runtime packages and profiles from DSH `0.1.1-rc.2` to `0.1.2-rc.1` at upstream commit `a66e4702047846cdaa10c66c9d3df3951f5ea70d`, with Cordis `4.0.2`, while preserving plugin contracts and keyless verification boundaries.

**Architecture:** Keep one current compatibility manifest for DSH/Cordis versions, align root/profile/plugin manifests and the lockfile, then adapt the three DSH-facing runtime areas independently: orchestrator, code intelligence, and telemetry. Extend the existing real Loader fixtures so every checked-in profile boots in its own dependency context, and finish with a non-workspace frozen-install consumer check.

**Tech Stack:** TypeScript ESM, Node.js `^22.19.0 || >=24`, pnpm `11.7.0`, Vitest `4.0.18`, TypeScript `5.9.3`, Cordis `4.0.2`, DeepSeek Harness `0.1.2-rc.1`, upstream tag commit `a66e4702047846cdaa10c66c9d3df3951f5ea70d`, and the existing DSH Loader/profile test harness.

**Spec:** `docs/superpowers/specs/2026-09-08-dsh-0.1.2-rc1-compatibility-design.md`

## Global Constraints

- Target all DSH packages at exact `0.1.2-rc.1`; do not introduce `0.1.3-alpha.2`.
- Target `@deepseek-ai/cordis` at exact `4.0.2`; keep Node.js and pnpm versions unchanged.
- Do not rewrite historical LSP candidate evidence in `scripts/check-dsh-plugin-candidate.mjs`, `tests/plugins/lsp-actions-compat.spec.ts`, or historical specs/plans.
- Preserve the existing uncommitted `package.json` repository-URL changes in `dsh-code-intelligence`, `dsh-context`, and `dsh-context-cache`; never stage them in migration commits.
- Provider calls, credentials, live network access, and real coding-task acceptance remain disabled and out of scope.
- Any changed submodule must record its starting HEAD and user diff in `HANDOFF.md`; only migration files may enter its commit.
- Every task ends with its focused validation and a commit whose staged paths exclude unrelated user changes.
