# DSH v0.2b Read-only Code Intelligence Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement keyless, fail-closed TypeScript/JavaScript repository snapshots, read-only LSP/fallback symbol indexing, bounded Repo Map and symbol-query projections, and the v0.2b baseline-versus-optimized evaluation gate without changing v0.1 orchestration behavior.

**Architecture:** Add a self-owned `@ds-plugins/dsh-code-intelligence` package between `@ds-plugins/dsh-context` and DSH tools. A deployment-root-bound snapshot store owns safe file receipts and repeat-checked source reads; a fixed-command LSP adapter may populate an internal index only when a host capability proves network isolation, otherwise a pinned TypeScript-AST fallback is used. Only parsed, cursor-based Repo Map and symbol-query DTOs cross the model boundary, and a separate v0.2b profile overlay exercises Loader composition without changing `profiles/v0.1`.

**Tech Stack:** TypeScript 5.9.3, Node.js 24 cached fallback, pnpm 11.7.0, Vitest 4.0.18, `@deepseek-ai/dsh-subprocess@0.1.1-rc.2`, `@deepseek-ai/dsh-tools@0.1.1-rc.2`, `@deepseek-ai/cordis@4.0.1`, `picomatch@4.0.7`, `tsdown@0.18.0`.

**Spec:** `docs/superpowers/specs/2026-08-29-dsh-v0.2-token-economy-design.md`

## Global Constraints

- Work only on branch `codex/v0.2b`; preserve all pre-existing user changes and use small task commits.
- Keep DeepSeek Harness pinned at `0.1.1-rc.2`; do not modify `upstream/deepseek-harness`.
- Do not modify Direct mode, Single Worker mode, `HandoffV1`, provider behavior, credentials, canonical v0.1 events, or `profiles/v0.1` semantics.
- Keep `pnpm test:provider` permanently keyless and disabled; no v0.2b test may access a provider, OAuth session, credential store, paid endpoint, or network.
- Do not implement a persistent cache, Context Block storage, cache hits, cache invalidation, progressive source expansion, or orchestrator context injection; those belong to v0.2c.
- Do not install or enable `dsh-lsp-actions`. Its reviewed status remains `patch-required`; this milestone implements a self-owned adapter and must not claim direct compatibility.
- Every filesystem operation is rooted at one deployment-controlled canonical root and reuses `assertSafeRepoPath`, `isIndexableFile`, `assertSnapshotHash`, and `sha256Utf8` from `@ds-plugins/dsh-context`.
- Every source read repeats containment, non-symlink regular-file, size, stat-signature, byte-length, and content-hash checks. Any mismatch fails closed.
- The LSP executable is an absolute, canonical, deployment-owned file; argv is a fixed string array; cwd is the canonical deployment root; stdin/stdout/stderr modes are explicit; no shell string is accepted.
- The LSP child receives an environment constructed by tombstoning every ambient key and adding only deployment-approved locale/temp entries. Credential, proxy, `DSH_*`, and network-related variables are never inherited.
- A JSON configuration flag is not proof of network isolation. The LSP process starts only when an injected host capability has `networkIsolation: 'enforced'`; otherwise it returns structured unavailable and the deterministic fallback is used.
- The internal `SymbolIndexV1` and full source text never become model-visible DTOs. Model-visible results use only `RepoMapPageV1` and `SymbolQueryResultV1` after their runtime parsers pass.
- Every model-visible result carries `snapshotId`; every item/match carries repository-relative path and source hash; every page is capped by entry count and UTF-8 serialized bytes and uses an opaque cursor bound to snapshot, query, offset, and policy version.
- Requests with stale snapshot IDs, stale/tampered cursors, unsupported language, malformed LSP frames, oversized output, path uncertainty, or incomplete provenance fail closed.
- v0.2b optimized evaluation uses no persistent cache. `cold` and `warm` protocol records both report `cache_hits: 0`, and `uncached_source_tokens` equals optimized model-visible source tokens; no cache benefit is claimed.
- The final gate must close both retained v0.2a findings: verifier paths cover all target and measured-source paths, and incomplete baseline groups return `invalid_pairing` even when no optimized records exist.
- Primary commands use `nix develop`; when Nix is unavailable, record the exact failure and use the bundled Node `/home/sihan/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin/node` with repository-local binaries. Do not hide environment failures.
