# DSH v0.2c Context Blocks and Bounded Cache Design

## Goal

Extend the keyless v0.2b retrieval layer with immutable, provenance-carrying context blocks, progressive source disclosure, a bounded persistent cache, and an optional orchestrator integration while preserving the v0.1 profile and provider-disabled boundary.

## Scope and non-goals

v0.2c covers context-block construction and integrity, cache lookup/write/invalidation/eviction/quarantine, bounded source-window expansion, context-aware read-only tools, and a separate v0.2c Loader profile. It does not change the Direct or Single Worker semantics used by `profiles/v0.1`, add provider calls, retain model transcripts, add write tools, or claim real coding-task acceptance.

## Architecture

`@ds-plugins/dsh-context` remains the authority for versioned contracts, canonical JSON, safe paths, hashes, and strict `ContextBlockV1` validation. A new `@ds-plugins/dsh-context-cache` package owns only persistence and cache policy; it accepts fully validated blocks and bounded JSON tool results, and knows nothing about Cordis or LSP internals. `@ds-plugins/dsh-code-intelligence` owns the compiler that adapts the existing snapshot/index projections into blocks and performs provenance-checked source expansion. `@ds-plugins/dsh-orchestrator` consumes an optional context compiler service through a separate v0.2c profile; its v0.1 profile stays unchanged.

The data flow is:

```text
snapshot + symbol index
        -> bounded Repo Map/Symbol Query projection
        -> ContextBlockBuilder
        -> cache lookup by boundary-aware key
        -> model-visible ContextBlockV1
        -> provenance-bearing source-window expansion
```

All model-visible values pass the strict parser and integrity checks immediately before return. A cache miss is safe and recomputes the value. A malformed, stale, oversized, out-of-bound, or corrupt value is never returned.

## Contracts

`ContextBlockV1` keeps the existing snake/camel-case contract:

```ts
type ContextBlockV1 = {
  schemaVersion: 1
  blockId: string
  kind: 'repo-map' | 'symbol' | 'source-window' | 'tool-result'
  workspaceFingerprint: string
  snapshotId: string
  adapterId: string
  adapterVersion: string
  compilerPolicyVersion: string
  sources: readonly { path: string; contentHash: string }[]
  contentHash: string
  text: string
  byteLength: number
  truncated: boolean
}
```

`buildContextBlock(input)` computes `contentHash` as SHA-256 over UTF-8 `text`, `byteLength` as the UTF-8 byte count, and `blockId` as SHA-256 over canonical JSON of every identity/content field except `blockId`, `contentHash`, `byteLength`, and `truncated`. It preserves source order, rejects duplicate or unsafe sources, and truncates only at UTF-8 code-point boundaries when a caller supplies a byte cap. `MAX_CONTEXT_BLOCK_BYTES` is exactly 65,536 and `MAX_CONTEXT_SESSION_BYTES` is exactly 262,144. `parseContextBlockV1` recomputes all derived fields and rejects unknown keys, forged hashes, invalid byte lengths, unsafe paths, duplicate sources, and oversized text.

The cache boundary is exact and includes `workspaceFingerprint`, `snapshotId`, `adapterId`, `adapterVersion`, `compilerPolicyVersion`, and `capabilityVersion`. Repository revision is metadata and a lookup hint, not a global invalidation key. A cache entry whose dependency source hash or boundary differs is a miss.

## Cache policy

The filesystem cache lives only under the trusted deployment root at `.dsh-context-cache/v1/`, using mode `0700` where supported. The snapshot scanner treats `.dsh-context-cache` as a hard exclusion before ignore traversal, so cache contents can never become repository source. It has separate `entries`, `lookups`, `quarantine`, and lock state. Entries are immutable JSON files keyed by content address; lookup records map normalized query/boundary keys to entry IDs and dependency hashes. Writes use a same-directory temporary file followed by atomic rename. A lock acquired with exclusive file creation serializes writers; lock timeout returns a cache miss rather than blocking model work indefinitely.

The live store is capped at 10,000 entries or 256 MiB, whichever is reached first. Eviction is deterministic least-recently-used by access timestamp, then entry ID. Corrupt or structurally invalid entries are renamed into quarantine and never returned. Quarantine is capped at 32 files or 10 MiB with oldest-first removal. Cache APIs never persist credentials, environment values, raw transcripts, diagnostics, or arbitrary paths.

`invalidateBySourceHashes(hashes)` removes only entries whose declared source dependencies include one of the hashes and removes lookup records pointing to them. Snapshot changes without changed dependency hashes do not cause a global flush; incomplete dependency information causes a miss.

## Compiler and progressive disclosure

The code-intelligence compiler exposes:

```ts
type ContextCompiler = {
  repoMap(request: RepoMapContextRequestV1, signal: AbortSignal): Promise<ContextBlockV1>
  symbolQuery(request: SymbolContextRequestV1, signal: AbortSignal): Promise<ContextBlockV1>
  expandSource(request: SourceExpansionRequestV1, signal: AbortSignal): Promise<ContextBlockV1>
}
```

Repo Map and Symbol Query blocks contain bounded JSON projections, not raw source. `expandSource` requires a cached/provenance-bearing `blockId`, a repository-relative path, and a bounded UTF-16 offset window. It verifies that the requested path/hash belongs to the source block, rereads the snapshot through the existing TOCTOU-safe store, applies per-block and per-session byte limits, and returns a `source-window` block. It rejects unknown block IDs, stale snapshots, altered source hashes, unsafe paths, overlapping/oversized windows, and expansion after the session budget is exhausted.

The v0.2c code-intelligence bundle adds context-specific read-only tools while retaining the two v0.2b projection tools for compatibility. The new tools return only parsed `ContextBlockV1` values and have no write, shell, provider, credential, or transcript capability.

## Orchestrator integration

The orchestrator adds an optional context service and one stable prompt section in a new v0.2c overlay. The section describes the initial-smallest-useful-context and provenance-required expansion policy without embedding provider/model values. The integration does not alter v0.1 `inject`, event schemas, budgets, worker behavior, or profile patch. Profile disposal removes the context prompt and all cache/compiler effects through the profile root.

The v0.2c profile composes the pinned DSH base, orchestrator, and code-intelligence bundle with an explicit cache policy. It is not included by `profiles/v0.1` and does not enable a provider or a write-capable tool.

## Evaluation and error handling

The optimized evaluator uses a fresh persistent cache for `cold` and a prescribed reused cache for `warm`, recording exact `cache_hits` and `cache_misses` while retaining the v0.2b reduction, recall, coverage, and oracle thresholds. Replay covers deterministic cold/warm hits, cross-boundary misses, source-hash invalidation, malformed and oversized entries, concurrent writers, quarantine limits, LRU eviction, lock timeout, stale block IDs, and UTF-8-safe truncation.

Missing optional services, cache corruption, lock contention, and unavailable LSP capabilities fail closed or fall back deterministically without provider access. Every timeout/cancellation path releases owned locks and process resources. The provider smoke command remains the exact keyless `DISABLED` check.

## Acceptance criteria

1. Context blocks are immutable, strictly hash-validated, bounded, provenance-carrying, and JSON-replayable.
2. Cache entries cannot cross workspace, snapshot, adapter, compiler-policy, capability, or dependency boundaries.
3. Persistent cache writes are atomic and single-writer; invalidation, eviction, quarantine, malformed input, concurrency, and UTF-8 truncation are tested.
4. Progressive source disclosure requires a valid prior block and enforces byte budgets.
5. Context tools remain read-only and bounded; the default v0.1 profile remains unchanged.
6. Cold and warm keyless replay/evaluation retain v0.2b thresholds and report hit/miss counts.
7. Targeted tests, typecheck, build, Loader/profile/replay checks, provider-disabled check, and `git diff --check` pass.
