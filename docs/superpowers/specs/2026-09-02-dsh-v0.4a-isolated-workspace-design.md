# DSH v0.4a Isolated Workspace and Ownership Infrastructure Design

## Goal

Provide the file-isolation and ownership-checking substrate that v0.4 Economical Multi-Agent parallel execution requires, under a deliberately implementable boundary: given one trusted deployment root and a validated DAG level, create N isolated workspace copies (one per worker), let each worker run in the shared working tree while reporting its changed files, extract the actual diff of each worker's isolated copy, verify every changed path against the worker's declared ownership (writePaths), integrate only ownership-valid accepted changes back into the shared tree as an all-or-nothing transaction, and clean up — all keyless, bounded, and replayable. v0.4a is a standalone package whose seam contract v0.4 consumes; it does not itself run workers or make scheduling decisions. Binding a worker's actual process cwd to its isolated copy (true execution isolation) is explicitly deferred to a future harness-upgrade / custom-provider milestone and is a non-goal here.

## Scope and non-goals

v0.4a covers: creation and lifecycle of N isolated workspace copies under a trusted isolation root; a deterministic immutable snapshot manifest of the deployment root at prepare time; per-worker actual diff extraction against that manifest (real filesystem diff, not self-reported changedFiles); ownership checking of every diff path against the declared writePaths grammar; all-or-nothing integration of accepted (ownership-valid) changes into the shared tree with typed conflict detection and rollback; workspace cleanup including git worktree registration release; bounded JSON seam contracts (PreparedLevelV1, OwnershipCheckV1, IntegrationResultV1) with strict parsers/schemas/freeze; and a keyless test gate that runs the same conformance suite against both a temporary Git repository and a non-Git directory. It does not implement worker execution, subagent lifecycle, per-worker process cwd binding (deferred), scheduling, budgets, Task DAG validation (v0.4), Handoff normalization, aggregation, or verification policy (v0.4). It does not modify upstream/deepseek-harness, does not require a network or provider, and does not claim real coding-task acceptance.

## Baseline and constraints

- Keep DeepSeek Harness pinned at 0.1.1-rc.2; do not fork or modify upstream/deepseek-harness.
- The isolation root is deployment-controlled and must be disjoint from the snapshot traversal; the repository already reserves and gitignores .worktrees/, and v0.4a defaults to <isolationRoot> = <deploymentRoot>/.worktrees/.dsh-v0.4a/<runId>/.
- Every seam input/output is a bounded JSON contract with strict parsers, schemas, deep-freeze, and no reference to Session, Agent, credentials, transcripts, authorization, or raw model output.
- Path grammar is authoritative in dsh-scheduling-contracts (shared with v0.4): canonical RepoFilePath (no trailing slash) and RepoDirectoryPrefix (trailing /); no glob metacharacters, . or .., drive roots, empty segments, NULs, or backslash; case-sensitive lexical containment. Filesystem symlink traversal checks happen at prepare/integration time via trusted-root canonicalization and lstat/realpath, not in the string parser.
- One immutable snapshot manifest is captured before any copy: for every in-scope path it records path, type, mode (where relevant), and content hash. In-scope = tracked files plus allowed untracked files; ignored paths (node_modules, lib, .git, .dsh, .dsh-context-cache, upstream, .worktrees) are excluded from the manifest and must be inaccessible to workers or reported as violations if a worker creates them.
- Both backends (git-worktree and file-copy) compare workers against the manifest, never against incidental HEAD state. Dirty tracked and allowed untracked files are captured as baseline content.
- Unknown filesystem states, unreadable paths, and symlink surprises fail closed with a typed error; nothing is silently skipped or estimated.

## Architecture

A standalone package depending only on the pure contracts package:

```text
packages/dsh-isolated-workspace/
  src/types.ts        # PreparedLevelV1, OwnershipCheckV1, IntegrationResultV1, seam option types, level handle
  src/parse.ts        # strict parsers + JSON schemas + freeze for every seam contract
  src/manifest.ts     # immutable snapshot manifest capture + in-scope/excluded rules
  src/backend.ts      # IsolatedWorkspaceSeam implementation (git-worktree or file-copy backend)
  src/integrate.ts    # all-or-nothing transactional integration + conflict detection + rollback
  src/index.ts        # public exports + package entry
```

The pure contract layer has no Cordis runtime dependency. The runtime backend depends only on Node filesystem primitives (or git via subprocess when the worktree backend is selected) and is injected into v0.4's Orchestrator as the isolatedWorkspace seam.

## Contracts

### PreparedLevelV1

```ts
interface PreparedWorkspaceV1 {
  readonly schemaVersion: 1
  readonly nodeId: string            // node identifier from the validated DAG
  readonly workerId: string          // opaque unique worker identifier scoped to this level (workerId !== nodeId by construction; mapping is returned here)
  readonly workspacePath: string     // absolute path of this worker's isolated copy
  readonly isolationRelativePath: string  // path relative to isolationRoot
}

interface PreparedLevelV1 {
  readonly schemaVersion: 1
  readonly levelId: string           // opaque unique level identifier; every later seam call takes it
  readonly runId: string
  readonly workspaces: readonly PreparedWorkspaceV1[]   // bounded by the v0.4 contracts MAX_PARALLEL_WORKERS
  readonly manifest: SnapshotManifestV1                 // immutable baseline captured at prepare time
}
```

### OwnershipCheckV1

```ts
interface OwnershipViolationV1 {
  readonly path: string               // repository-relative changed path outside declared ownership
  readonly workerId: string
}

interface OwnershipCheckV1 {
  readonly schemaVersion: 1
  readonly workerId: string
  readonly declaredWritePaths: readonly string[]
  readonly actualChangedPaths: readonly string[]        // every path changed in this worker's copy, diffed against the manifest
  readonly violations: readonly OwnershipViolationV1[]  // actualChangedPaths not contained by any declaredWritePaths
  readonly valid: boolean                                // violations.length === 0
}
```

### IntegrationResultV1

```ts
interface IntegrationResultV1 {
  readonly schemaVersion: 1
  readonly integratedWorkerIds: readonly string[]        // empty unless status === 'completed'
  readonly conflicts: readonly {
    readonly workerId: string
    readonly path: string
    readonly reason: 'overlap' | 'already-modified' | 'missing-base'
  }[]
  readonly appliedChanges: readonly string[]             // empty unless status === 'completed'
  readonly status: 'completed' | 'conflicts' | 'failed'
}
```

parsePreparedLevelV1, parseOwnershipCheckV1, and parseIntegrationResultV1 validate, bound, and deep-freeze each contract. SnapshotManifestV1 is bounded (path count, per-path hash length, total UTF-8 payload cap). MAX_ISOLATED_WORKSPACE_BYTES (per-copy logical source byte cap, checked before and after worker changes), MAX_DIFF_PATHS, and MAX_INTEGRATION_CONFLICTS are exported constants; the worker-count bound is imported from the v0.4 scheduling contracts.

### Seam interface (level-handle based, signal-aware)

```ts
interface IsolatedWorkspaceSeam {
  prepareLevel(request: PrepareLevelRequestV1, signal: AbortSignal): Promise<PreparedLevelV1>
  diffAndCheck(levelHandle: LevelHandleV1, workerId: string, declaredWritePaths: readonly string[], signal: AbortSignal): Promise<OwnershipCheckV1>
  integrateAccepted(levelHandle: LevelHandleV1, workerIds: readonly string[], signal: AbortSignal): Promise<IntegrationResultV1>
  disposeLevel(levelHandle: LevelHandleV1): Promise<void>
}
```

LevelHandleV1 is an opaque bounded token returned by prepareLevel and required by every later operation. Distinct levels (including concurrent root sessions) never share hidden state; disposeLevel(levelHandle) affects only that level and waits for in-flight diff/integration on it to settle.

## Isolation backend behavior

- prepareLevel(request, signal): capture the immutable snapshot manifest first, then under <isolationRoot>/<runId>/<levelId>/ create one copy per node. Git-worktree backend: git worktree add --detach per node from the manifest revision, then materialize the manifest's dirty tracked + allowed untracked baseline content into each worktree. File-copy backend: recursive copy of the in-scope manifest tree, skipping the excluded set. Both backends produce identical seam behavior. All-or-nothing per level: on any failure, roll back already-created copies and reject.
- Worker execution (in v0.4) remains in the shared working tree exactly as today's Single Worker path; each worker self-reports changedFiles. v0.4a does not bind worker cwd (deferred non-goal). The isolated copies exist so diffAndCheck can compute what the worker actually changed without trusting the self-report.
- diffAndCheck(levelHandle, workerId, declaredWritePaths, signal): compute the actual changed paths in that worker's copy relative to the manifest (git backend: compare worktree against manifest revision plus materialized baseline; file backend: compare against stored manifest), normalize each via the shared grammar, and report every path not contained by declared ownership as a violation.
- integrateAccepted(levelHandle, workerIds, signal): all-or-nothing transaction per level. Preflight every affected path's base receipt (shared tree must equal the manifest baseline for that path), detect cross-worker overlaps, then apply the merged accepted-worker changes. On any conflict or write failure, roll back to the pre-integration state and return status 'conflicts' or 'failed' with EMPTY integratedWorkerIds and appliedChanges. A deployment-root integration lock serializes concurrent integrations; concurrent levels from different sessions cannot race past the guard.
- disposeLevel(levelHandle): remove the level's isolation copies, release git worktree registration (git worktree remove, filesystem fallback, git worktree prune), best-effort and idempotent, and safe under cancellation. Stale-run recovery and cleanup-failure results are typed and logged.

## Safe degradation and errors

- Missing isolation root, unwritable path, failed copy, or failed git worktree add → typed error, all-or-nothing prepare rollback, no partial state.
- A worker whose copy cannot be diffed → that worker is reported failed by the consumer, never integrated.
- A conflict or integration failure → status 'conflicts'/'failed', empty integrated/applied sets, no partial silent merge; v0.4 decides continuation.
- Symlinks, special files, and paths outside the deployment root are rejected by prepare/integration canonicalization and fail closed.
- Cleanup runs on success, failure, and cancellation paths; disposeLevel is idempotent and level-scoped.

## Evaluation and error handling

Keyless test gate (real temp directories; no provider/network/paid calls) runs one conformance suite against two mandatory fixtures: a temporary Git repository (git backend) and a non-Git directory (file-copy backend). The suite covers:

- manifest: in-scope/excluded rules, dirty tracked + allowed untracked baseline capture, ignored-path exclusion, bounded payload.
- prepareLevel: N copies created under isolation root, all-or-nothing rollback on failure, bounded workspace count, distinct level handles isolate concurrent levels.
- diffAndCheck: real file mutations in a copy produce actualChangedPaths; a change outside declared ownership is a violation; a change inside ownership is valid; a worker-created ignored path is reported as a violation; add/delete/modify/rename/type-change semantics are consistent across both backends.
- integrateAccepted: ownership-valid changes apply as one transaction; cross-worker overlap and already-modified conflicts are reported; on conflict/failure integratedWorkerIds and appliedChanges are empty; rollback restores the pre-integration tree; concurrent integration is serialized by the lock.
- disposeLevel: copies removed, git worktree list --porcelain has no registration after success/failure/cancellation, idempotent, level-scoped.

The package test command is test:v0.4a (package unit tests + package-entry smoke over both backends), plus typecheck/build and git diff --check. Provider smoke remains the exact keyless DISABLED check.

## Acceptance criteria

1. prepareLevel/diffAndCheck/integrateAccepted/disposeLevel implement the bounded, level-handle-based, signal-aware seam contract with strict parsers/schemas/freeze.
2. Ownership is enforced from the actual diff of each isolated copy against the immutable manifest, never from self-reported changedFiles; violations fail closed and are never integrated.
3. Integration is all-or-nothing per level: on conflict/failure, integratedWorkerIds and appliedChanges are empty and the shared tree is rolled back to baseline.
4. Isolation copies are bounded, all-or-nothing per level, cleaned up on success/failure/cancellation, and git worktree registrations are fully released.
5. The same conformance suite passes against both a temporary Git repository and a non-Git directory (both backends mandatory, no skip).
6. The path grammar and constants come from dsh-scheduling-contracts (single authoritative source, no duplication, no dependency cycle).
7. profiles/v0.1 is untouched; no runtime plugin, worker execution, per-worker cwd binding (deferred), scheduling, DAG validation, or budget logic lives in this package.
8. test:v0.4a, typecheck, build, provider-disabled check, and git diff --check pass.

## Relationship to v0.4 and deferred execution isolation

v0.4 consumes this package's seam through an injected isolatedWorkspace service and fakes it in its own keyless replay gate. v0.4a is the real backend and is verified independently with real temporary filesystems. The two versions share the path grammar/constants in dsh-scheduling-contracts and the PreparedLevelV1/OwnershipCheckV1/IntegrationResultV1 contracts, so v0.4's fake and v0.4a's real backend are drop-in interchangeable.

True per-worker execution isolation (binding each spawned child's process cwd/fs root to its isolated copy) is deferred: the pinned Harness 0.1.1-rc.2 SubagentStartRequest has no workspace/cwd field, and the in-process spawn provider inherits the parent cwd. v0.4a deliberately does not claim to prevent an already-written out-of-ownership mutation in the shared tree; it guarantees that such a mutation is detected (diff-derived) and never integrated, and that accepted changes are integrated transactionally. Execution isolation becomes a separate milestone gated on a Harness upgrade or a DSH-owned custom subagent provider that stamps child session cwd.
