# DSH v0.4a Isolated Workspace Infrastructure Design

## Goal

Provide the physical per-worker file isolation that v0.4 Economical Multi-Agent parallel execution requires: given one trusted deployment root and a validated DAG level, create N isolated workspace copies (one per worker), let each worker mutate only its own copy, extract the actual diff per worker, verify every changed path against the worker's declared ownership (writePaths), integrate only ownership-valid accepted changes back into the shared working tree, and clean up — all keyless, bounded, and replayable. v0.4a is a standalone package whose seam contract v0.4 consumes; it does not itself run workers or make scheduling decisions.

## Scope and non-goals

v0.4a covers: creation and lifecycle of N isolated workspace copies under a trusted isolation root; a deterministic diff extraction per worker (real filesystem diff, not self-reported changedFiles); ownership checking of every diff path against the declared writePaths grammar; integration of accepted (ownership-valid) changes into the shared tree with conflict detection; workspace cleanup; bounded JSON seam contracts (PreparedLevelV1, OwnershipCheckV1, IntegrationResultV1); and a keyless test gate using real temporary directories but no provider/network/paid calls. It does not implement worker execution, subagent lifecycle, scheduling, budgets, Task DAG validation (v0.4), Handoff normalization, aggregation, or verification policy (v0.4). It does not modify upstream/deepseek-harness, does not require a network or provider, and does not claim real coding-task acceptance.

## Baseline and constraints

- Keep DeepSeek Harness pinned at 0.1.1-rc.2; do not fork or modify upstream/deepseek-harness.
- The isolation root is a deployment-controlled trusted path; the repository already reserves and gitignores .worktrees/ for isolated feature worktrees. v0.4a defaults to creating isolation under a deployment-controlled root such as .worktrees/.dsh-v0.4a/<runId>/.
- Every seam input/output is a bounded JSON contract with strict parsers, schemas, deep-freeze, and no reference to Session, Agent, credentials, transcripts, authorization, or raw model output.
- Path grammar is the v0.4 small grammar: normalized POSIX repository-relative file paths or directory prefixes ending in /; no glob metacharacters, . or .., drive roots, empty segments, NULs, or symlink traversal; case-sensitive lexical containment.
- Isolation copies are created from a trusted snapshot of the deployment root's repository state; the mechanism may use git worktree (when the root is a git checkout) or a deterministic file-tree copy (when it is not), selected by a deployment flag, but the seam contract is identical for both backends.
- No worker or tool ever writes outside its isolated copy; enforcement is by the isolation backend (each worker's execution points at its own copy) plus diff-derived ownership checking at integration time.
- Unknown filesystem states, unreadable paths, and symlink surprises fail closed with a typed error; nothing is silently skipped or estimated.

## Architecture

A standalone package:

```text
packages/dsh-isolated-workspace/
  src/types.ts        # PreparedLevelV1, OwnershipCheckV1, IntegrationResultV1, seam option types
  src/parse.ts        # strict parsers + JSON schemas + freeze for every seam contract
  src/grammar.ts      # canonical path normalization + containment + ownership matching (shared grammar)
  src/backend.ts      # IsolatedWorkspaceSeam implementation (git-worktree or file-copy backend)
  src/index.ts        # public exports + package entry
```

It has no Cordis runtime dependency in the pure contract layer. The runtime backend depends only on Node filesystem primitives (or git via subprocess when the worktree backend is selected) and is injected into v0.4's Orchestrator as the `isolatedWorkspace` seam.

## Contracts

### Path grammar (shared with v0.4)

```ts
// canonicalizePath(value): POSIX repository-relative, no ./.., no trailing slash except root '/', no NUL, no backslash, no drive root
// isContainedBy(path, prefix): prefix is a file path and path === prefix, or prefix ends in '/' and path starts with prefix
// normalizeDeclaredPaths(values): dedupe + reject overlaps within one node
```

### PreparedLevelV1

```ts
interface PreparedWorkspaceV1 {
  readonly schemaVersion: 1
  readonly workerId: string           // nodeId-scoped worker identifier
  readonly workspacePath: string      // absolute path of this worker's isolated copy
  readonly relativeRoot: string       // repository-relative path of the copy root inside the deployment root
}

interface PreparedLevelV1 {
  readonly schemaVersion: 1
  readonly levelId: string
  readonly runId: string
  readonly workspaces: readonly PreparedWorkspaceV1[]   // bounded by the v0.4 contracts MAX_PARALLEL_WORKERS
  readonly snapshotRevision?: string   // repository revision the copies were made from, when known
}
```

### OwnershipCheckV1

```ts
interface OwnershipViolationV1 {
  readonly path: string               // repository-relative changed path outside declared ownership
  readonly workerId: string
}

interface OwnershipCheckV1 {
  readonly schemaVersion: 1
  readonly workerId: string
  readonly declaredWritePaths: readonly string[]
  readonly actualChangedPaths: readonly string[]        // every path changed in this worker's copy (diff-derived)
  readonly violations: readonly OwnershipViolationV1[]  // actualChangedPaths not contained by any declaredWritePaths
  readonly valid: boolean                                // violations.length === 0
}
```

### IntegrationResultV1

```ts
interface IntegrationResultV1 {
  readonly schemaVersion: 1
  readonly integratedWorkerIds: readonly string[]        // ownership-valid workers whose changes were applied
  readonly conflicts: readonly {
    readonly workerId: string
    readonly path: string
    readonly reason: 'overlap' | 'already-modified' | 'missing-base'
  }[]
  readonly appliedChanges: readonly string[]             // repository-relative paths applied to the shared tree
  readonly status: 'completed' | 'conflicts' | 'failed'
}
```

`parsePreparedLevelV1`, `parseOwnershipCheckV1`, and `parseIntegrationResultV1` validate, bound (bounded counts, bounded UTF-8 payloads), and deep-freeze each contract. `MAX_ISOLATED_WORKSPACE_BYTES`, `MAX_DIFF_PATHS`, and `MAX_INTEGRATION_CONFLICTS` are exported constants; the worker-count bound is imported from the v0.4 scheduling contracts.

## Isolation backend behavior

- prepareLevel(nodes): under `<isolationRoot>/<runId>/<levelId>/`, create one copy per node. Git-worktree backend: `git worktree add --detach` per node from the current HEAD (or an explicit snapshot revision), then copy any uncommitted working-tree state the deployment trusts. File-copy backend: recursive copy of the trusted snapshot tree, skipping node_modules/lib/.git/.dsh/.dsh-context-cache/upstream per the existing ignore set.
- Every worker's execution (in v0.4) points its filesystem tools at its own `workspacePath`; v0.4a itself does not start workers.
- diffAndCheck(workerId, declaredWritePaths): compute the actual changed paths in that worker's copy relative to the snapshot (git backend: `git diff --name-only` plus untracked; file backend: compare against the stored snapshot manifest), normalize each via the shared grammar, and report every path not contained by declared ownership as a violation.
- integrateAccepted(workerIds): apply each accepted worker's diff to the shared tree. A change is applied only when the target path is unmodified in the shared tree since the snapshot (version-guarded). Conflicts (overlap between two workers, already-modified in shared tree, or missing base) are reported, never silently overwritten. Applied changes are recorded; nothing outside accepted worker diffs is touched.
- disposeLevel(): remove the level's isolation copies and release any git worktree registration, best-effort, idempotent, and safe under cancellation.

## Safe degradation and errors

- Missing isolation root, unwritable path, failed copy, or failed git worktree add → typed error, no partial integration, no silent skip. prepareLevel is all-or-nothing per level (roll back already-created copies on failure).
- A worker whose copy cannot be diffed → that worker is reported failed, never integrated.
- A conflict at integration → IntegrationResultV1.status = 'conflicts' with per-path reasons; no partial silent merge; v0.4 decides continuation.
- Symlinks, special files, and paths outside the deployment root are rejected by the grammar/backend and fail closed.
- Cleanup runs on success, failure, and cancellation paths; disposeLevel is idempotent.

## Evaluation and error handling

Keyless test gate covers (real temp directories; no provider/network/paid calls):

- grammar: canonicalization, containment, declared-path dedupe/overlap rejection, traversal/absolute/Windows/symlink rejection.
- prepareLevel: N copies created under isolation root, all-or-nothing rollback on failure, bounded workspace count.
- diffAndCheck: real file mutations in a copy produce actualChangedPaths; a change outside declared ownership is a violation; a change inside ownership is valid; self-reported vs actual-diff mismatch is impossible by construction (diff is actual).
- integrateAccepted: ownership-valid changes apply; cross-worker overlap and already-modified conflicts are reported; no silent overwrite; applied paths recorded.
- disposeLevel: copies removed, idempotent, safe on cancellation.
- Both backends (git-worktree when the repo permits, file-copy otherwise) produce identical seam contract behavior on the same fixture.

The package test command is `test:v0.4a` (package unit tests + package-entry smoke), plus typecheck/build and `git diff --check`. Provider smoke remains the exact keyless DISABLED check.

## Acceptance criteria

1. prepareLevel/diffAndCheck/integrateAccepted/disposeLevel implement the bounded seam contract with strict parsers/schemas/freeze.
2. Ownership is enforced from the actual diff of each isolated copy, never from self-reported changedFiles; violations fail closed and are never integrated.
3. Integration applies only ownership-valid accepted changes, version-guarded, with typed conflict reporting and no silent overwrite.
4. Isolation copies are bounded, all-or-nothing per level, and cleaned up on success/failure/cancellation.
5. Both git-worktree and file-copy backends satisfy the same seam contract on the same fixture, keyless.
6. The path grammar matches v0.4's ownership grammar exactly.
7. `profiles/v0.1` is untouched; no runtime plugin, worker execution, scheduling, DAG validation, or budget logic lives in this package.
8. `test:v0.4a`, typecheck, build, provider-disabled check, and `git diff --check` pass.

## Relationship to v0.4

v0.4 consumes this package's seam through an injected `isolatedWorkspace` service and fakes it in its own keyless replay gate. v0.4a is the real backend and is verified independently with real temporary filesystems. The two versions share the path grammar and the PreparedLevelV1/OwnershipCheckV1/IntegrationResultV1 contracts, so v0.4's fake and v0.4a's real backend are drop-in interchangeable.
