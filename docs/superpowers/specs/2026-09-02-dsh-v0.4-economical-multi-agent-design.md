# DSH v0.4 Economical Multi-Agent Design

## Goal

Extend the Orchestrator so it can decompose a root task into bounded, independent sub-tasks and run them as parallel Workers with disjoint file ownership, then aggregate their Handoffs and verify the integrated result — while preserving the keyless v0.3 safety boundary, deterministic replay, and the single-monorepo plugin ownership model. v0.4 introduces a declarative Task DAG and independence/ownership validation as deterministic pure logic in the Orchestrator, plus a bounded parallel-worker execution path, Handoff aggregation, and context-locality/reuse admission rules. No new runtime plugin is created; the Adaptive Scheduler continues to own resource/affinity selection.

## Scope and non-goals

v0.4 covers: the contracts needed for bounded parallel workers and task graphs; a deterministic, replayable Task DAG representation with file-ownership sets and dependency edges; parallel fan-out with disjoint write-set enforcement; Handoff aggregation and integrated-result verification; a deterministic keyless replay gate for the parallel path; and reuse/context-locality admission rules that are safe to replay. It does not implement learning-based decomposition or LLM Judge independence approval, real warm mutable worker reuse across tasks, cross-session physical worker pooling, workspace/worktree isolation infrastructure, recursive worker delegation beyond maxDepth 1, or any provider/network/real coding-task acceptance. It does not modify `profiles/v0.1`, the Direct or Single Worker semantics, `HandoffV1` projection semantics, `BudgetController` admission exclusivity, or the `run-started` actual-route projection.

## Baseline and constraints

- Keep DeepSeek Harness pinned at `0.1.1-rc.2` until a separate compatibility review proves an upgrade.
- Preserve Direct mode, Single Worker mode, `HandoffV1`, plugin-owned budgets, targeted verification, canonical `dsh-plugin/` events, and the keyless `DISABLED` provider smoke.
- The Orchestrator owns task DAG, independence/ownership validation, worker lifecycle, final budget admission, Handoff normalization/aggregation, and event recording. The Scheduler only provides capability-to-schedule decisions.
- Do not fork or modify `upstream/deepseek-harness` or replace its agent loop.
- All model-visible outputs and all orchestration evidence stay bounded, provenance-carrying, and safe to replay.
- No orchestration decision may bypass the Orchestrator's hard constraints (`maxWorkers`, `maxPluginToolActions`, tool allowlist, workspace/verification policy, disjoint ownership).
- Parallel fan-out uses only `ctx.subagents.start()` for distinct children; the Harness provider contract already allows concurrent distinct children. Worker reuse across tasks is limited to deterministic, replay-safe admission rules; no mutable warm worker pool is created in v0.4.
- Unknown quota, price, or health values are never invented or silently estimated into hard routing decisions.

## Architecture

The repository keeps the existing packages and adds no new runtime plugin. v0.4 extends the Orchestrator-owned DAG/ownership/parallel layer and the pure contracts package:

```text
packages/
  dsh-scheduling-contracts/   # pure types, JSON schema, parsers; no Cordis runtime
  dsh-orchestrator/           # gains task DAG, independence/ownership validation, parallel fan-out, aggregation
```

`dsh-scheduling-contracts` already defines `CapabilityRequestV1`, `RouteDecisionV1`, `ScheduleDecisionV1`, `BudgetViewV1`, `ScheduleFeedbackV1`, and `ScheduleSelectedV1`. v0.4 widens the bounded worker model in place (see Contracts), adds the Task DAG contracts, and keeps the no-Cordis boundary.

`dsh-orchestrator` adds a deterministic pure `dag.ts` module (DAG construction, cycle rejection, level/topological ordering, independence check, disjoint write-set validation, and read/write ownership projection) and extends the worker path so `delegate_worker` can admit and run N bounded workers with per-worker route selection, then aggregate Handoffs into a parent-level result. Root route selection remains under the existing Adaptive Scheduler seam.

The execution flow:

```text
root task
  -> decompose (declarative sub-task spec: objective, read/write sets, dependencies)
  -> Orchestrator DAG validation (pure): acyclic, disjoint write sets, bounded workers, maxDepth 1
  -> per-level schedule: Adaptive Scheduler selects route/workerCount per capability request
  -> Orchestrator hard validation + BudgetController final admission (N workers bounded)
  -> parallel subagents.start('spawn') for ready level
  -> per-worker Handoff normalization
  -> aggregate Handoffs + integrated-result verification
  -> dsh-plugin durable events per worker and aggregate
```

## Contracts

### Task DAG

```ts
interface TaskNodeV1 {
  readonly schemaVersion: 1
  readonly nodeId: string              // unique within the graph
  readonly objective: string
  readonly profile: CapabilityProfileV1
  readonly constraints: SchedulingConstraintsV1
  readonly readPaths: readonly string[]     // repository-relative path patterns
  readonly writePaths: readonly string[]    // repository-relative path patterns (ownership)
  readonly dependsOn: readonly string[]     // nodeIds that must complete first
  readonly requiredTools: readonly string[]
}

interface TaskDagV1 {
  readonly schemaVersion: 1
  readonly rootTaskId: string
  readonly nodes: readonly TaskNodeV1[]
}
```

### Independence and ownership

```ts
type DagValidationIssueV1 =
  | { code: 'cycle'; nodeId: string }
  | { code: 'duplicate-node'; nodeId: string }
  | { code: 'missing-dependency'; nodeId: string; dependsOn: string }
  | { code: 'overlapping-write'; nodeA: string; nodeB: string }
  | { code: 'write-outside-root'; nodeId: string; path: string }
  | { code: 'too-many-workers'; nodeId: string; limit: number }
  | { code: 'depth-exceeded'; nodeId: string }

interface DagValidationV1 {
  readonly schemaVersion: 1
  readonly valid: boolean
  readonly issues: readonly DagValidationIssueV1[]
  readonly levels: readonly (readonly string[])[]
  readonly maxDepth: number
}
```

`validateTaskDagV1(dag, config)` returns a frozen `DagValidationV1`. A graph is valid only when every node is acyclic, unique, dependencies exist, write sets are pairwise disjoint after canonical path normalization, no write path escapes the deployment root, worker count per level is within the configured bound, and depth never exceeds 1. `levels` is the deterministic topological level ordering used for parallel admission.

### Widened worker model

`SchedulingConstraintsV1.maxWorkers` becomes a bounded integer `0..MAX_PARALLEL_WORKERS` (new exported constant, default 8); `ScheduleDecisionV1.mode` adds `'parallel-workers'`; `workerCount` becomes `0..MAX_PARALLEL_WORKERS`. `direct` requires `workerCount: 0`; `single-worker` requires `1`; `parallel-workers` requires `2..MAX`. The existing v0.3 rejection logic for unconfigured providers, over-limit tokens, and empty routes is preserved. Parser guards, exact-record field lists, JSON-schema enums/maximums, and budget derived-counter invariants are updated in lockstep with the types. Existing `single-worker` and `direct` fixtures/tests remain valid; tests that assert rejection of `workerCount > 1` are updated to assert the new parallel bound instead.

### Budget view

`BudgetViewV1.maxWorkers` and derived counters become bounded by `MAX_PARALLEL_WORKERS`. `BudgetController` keeps admission exclusive to the Orchestrator; a parallel fan-out performs N synchronous admissions up to the configured bound, and any admission failure rolls back the already-admitted workers for that fan-out before any child starts.

### Feedback and aggregation

Each parallel worker emits its own `ScheduleFeedbackV1` with the existing outcome union; the Orchestrator additionally produces an aggregate Handoff record for the fan-out that references each worker's `requestId`/Handoff and the integrated verification result. No worker transcript, raw output, credential, or authorization enters the aggregate.

### Durable events

Existing per-worker events (`schedule-selected` target=worker, `worker-requested`, `worker-finished`) are preserved one per worker with the worker index/nodeId in the bounded payload. v0.4 adds one aggregate event `dsh-plugin/parallel-finished` carrying the fan-out id, worker count, per-worker requestIds, aggregate Handoff status, and integrated verification outcome — no raw output, no transcript.

## Decision precedence

The Orchestrator owns DAG/ownership decisions. Resource decisions keep the v0.3 scheduler precedence, extended so a parallel request is scheduled per worker capability request; the Scheduler cannot change the DAG, write sets, or worker count beyond the validated bound. When the Scheduler is absent, the Profile fixed route is used per worker.

## Parallel execution model

- A DAG may have dependency chains across levels; a fan-out runs only the ready nodes of one level, and a level completes when every worker Handoff is normalized and recorded. `maxDepth: 1` means each worker is a leaf that never recursively delegates; it does not forbid dependency levels in the root-owned graph.
- Each worker is a fresh `subagents.start('spawn')` child with `maxDepth: 1`, frozen route, and an allow-only tool filter including targeted verification.
- Write-set enforcement is deterministic: the Orchestrator compares each returned Handoff's `changedFiles` against the node's declared `writePaths`; a worker that writes outside its ownership fails closed and its Handoff is marked conflict/invalid, never merged silently.
- Workers that fail, block, or produce invalid Handoffs do not abort healthy siblings by default; the aggregate reports each status and the Orchestrator decides continuation under budget.
- Integrated-result verification runs once on the union of accepted worker changes (or on the working tree state the profile allows) rather than redundantly per worker.

## Context locality and reuse admission (v0.4 deterministic subset)

v0.4 does not create a mutable warm worker pool. Instead it implements deterministic, replay-safe context-locality rules:

- A `ContextLocalityKeyV1` = ordered hash of stable prefix components: pinned system prompt hash, canonical tool-schema ordering, profile/policy version, repo revision, and workspace fingerprint.
- Two capability requests with the same key and compatible budgets may share the same logical route/affinity snapshot for replay provenance; the Orchestrator records this as `contextReuse: 'prefix-compatible'` in the aggregate event.
- Reuse admission rules are pure and replayable: identical key + disjoint ownership + same model family + same budget class → eligible for prefix-compatible scheduling; anything else → fresh worker.
- No worker retains mutable session state across tasks in v0.4. Real warm mutable reuse (continuable children, session persistence, cross-task context carry) is a post-v0.4 item gated on provider/keyless evidence.

## Safe degradation

- No Scheduler → per-worker Profile fixed route, deterministic and keyless.
- Scheduler invalid/out-of-bound decision → same validation failure and fallback policy as v0.3; never silently expands worker count or provider.
- Ownership violation → fail closed, record issue, never merge.
- DAG invalid (cycle/overlap/too many) → reject fan-out before admission, record issue, no budget consumed.
- Provider auth/quota/rate-limit errors never trigger silent paid fallback.
- `run-started` keeps actual-route semantics.

## Evaluation and error handling

Keyless replay covers:

- DAG validation: valid acyclic graph, cycle rejection, missing dependency, overlapping write sets, write-outside-root, too-many-workers, depth-exceeded.
- Parallel fan-out admission: N workers within bound, rollback on partial admission failure, no child start before all admissions succeed.
- Per-worker route selection (scheduler-present and profile-fallback).
- Per-worker Handoff normalization and ownership enforcement (changedFiles vs writePaths).
- Aggregate Handoff + integrated-result verification.
- Event provenance: per-worker `worker-requested`/schedule-selected/worker-finished plus one aggregate `parallel-finished`; ordering and bounded payloads.
- Context-locality admission: prefix-compatible reuse decision vs fresh worker, deterministic and replayable.
- Profile-fallback, invalid-decision, quota/timeout/cooldown, escalation, Direct actual-route, and read-only budget snapshot regressions remain green.

Missing optional services, invalid decisions, quota failures, and unknown provider/model values fail closed or degrade deterministically without provider access. Every timeout/cancellation path releases owned resources. The provider smoke command remains the exact keyless `DISABLED` check.

## Acceptance criteria

1. The Task DAG contracts and validator are pure, deterministic, bounded, and keyless; cycle/overlap/ownership/depth/worker-count issues are rejected before admission.
2. Parallel fan-out runs N bounded workers with per-worker route selection, disjoint write-set enforcement, and rollback-safe admission.
3. Each worker emits the existing per-worker durable events; one aggregate `parallel-finished` event carries bounded fan-out provenance and integrated verification outcome.
4. Ownership violations and invalid DAGs fail closed without budget consumption or silent merge.
5. Context-locality/reuse admission is deterministic and replay-safe; no mutable warm worker pool exists in v0.4.
6. Direct, Single Worker, Handoff, budget, targeted verification, canonical events, Adaptive Scheduler, and keyless `DISABLED` smoke semantics remain intact.
7. `profiles/v0.1` remains byte-for-byte unchanged; a v0.4 profile (if added) composes base + Orchestrator + Adaptive Scheduler with explicit bounds.
8. Targeted tests, typecheck, build, Loader/profile/replay checks, provider-disabled check, and `git diff --check` pass.
