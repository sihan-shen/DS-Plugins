# DSH v0.4 Economical Multi-Agent Design

## Goal

Extend the Orchestrator so it can decompose a root task into bounded, independent sub-tasks and run them as parallel Workers whose file mutations are physically isolated per worker, then aggregate their Handoffs and verify the integrated result — while preserving the keyless v0.3 safety boundary, deterministic replay, and the single-monorepo plugin ownership model. v0.4 introduces a declarative Task DAG and independence/ownership validation as deterministic pure logic in the Orchestrator, plus a bounded parallel-worker execution path, Handoff aggregation, and an integrated-result verification gate. Physical per-worker workspace isolation and diff-derived ownership enforcement are provided by the separate v0.4a Isolated Workspace Infrastructure package, whose contract v0.4 consumes through an injected seam; v0.4 itself does not implement filesystem isolation. No new runtime plugin beyond the Orchestrator is created; the Adaptive Scheduler continues to own resource/affinity selection.

## Scope and non-goals

v0.4 covers: the contracts needed for bounded parallel workers and task graphs; a deterministic, replayable Task DAG representation with file-ownership sets and dependency edges; a parallel fan-out path that consumes the v0.4a isolation seam (each worker edits only its own isolated copy, integration is diff-derived and ownership-checked); per-worker Handoff normalization plus a strict ParallelAggregateV1 result; integrated-result verification; and a deterministic keyless replay gate. It does not implement filesystem/worktree isolation, snapshot/diff extraction, patch integration, or conflict handling — those are v0.4a. It does not implement learning-based decomposition, LLM Judge independence approval, mutable warm worker reuse across tasks, cross-session physical worker pooling, recursive worker delegation beyond subagentMaxDepth 1, or any provider/network/real coding-task acceptance. Context-locality/prefix-compatible reuse and all deferred v0.3 roadmap items (hysteresis, shadow Judge, quota adapters) are explicitly deferred beyond v0.4. It does not modify profiles/v0.1, the Direct or Single Worker semantics, HandoffV1 projection semantics, BudgetController admission exclusivity, or the run-started actual-route projection.

## Baseline and constraints

- Keep DeepSeek Harness pinned at 0.1.1-rc.2 until a separate compatibility review proves an upgrade.
- Preserve Direct mode, Single Worker mode, HandoffV1, plugin-owned budgets, targeted verification, canonical dsh-plugin/ events, and the keyless DISABLED provider smoke.
- The Orchestrator owns task DAG, independence/ownership validation, worker lifecycle, final budget admission, Handoff normalization/aggregation, and event recording. The Scheduler only provides capability-to-schedule decisions. The v0.4a isolation seam is injected and never owns orchestration state.
- Do not fork or modify upstream/deepseek-harness or replace its agent loop.
- All model-visible outputs and all orchestration evidence stay bounded, provenance-carrying, and safe to replay.
- No orchestration decision may bypass the Orchestrator's hard constraints (maxWorkers, maxPluginToolActions, tool allowlist, workspace/verification policy, disjoint ownership).
- Parallel fan-out uses only ctx.subagents.start() for distinct children; the Harness provider contract already allows concurrent distinct children. Physical isolation of each child's file mutations comes from the v0.4a seam; v0.4 never lets a worker mutate a shared working tree outside its isolated copy.
- Unknown quota, price, or health values are never invented or silently estimated into hard routing decisions.
- No v0.4 profile is added; the parallel path is validated by a new keyless replay fixture over the v0.3-adaptive profile and the v0.4a isolation seam fake. profiles/v0.1 remains byte-for-byte unchanged.

## Architecture

The repository keeps the existing packages and adds no new runtime plugin. v0.4 extends the Orchestrator-owned DAG/ownership/parallel layer and the pure contracts package; v0.4a (separate spec) supplies the isolation seam:

```text
packages/
  dsh-scheduling-contracts/   # pure types, JSON schema, parsers; no Cordis runtime (v0.4 widens worker model + adds DAG/aggregate contracts)
  dsh-isolated-workspace/     # v0.4a package: snapshot/copy, diff, ownership check, patch integration; consumed via injected seam
  dsh-orchestrator/           # gains task DAG, independence/ownership validation, parallel fan-out, aggregation
```

dsh-scheduling-contracts already defines CapabilityRequestV1, RouteDecisionV1, ScheduleDecisionV1, BudgetViewV1, ScheduleFeedbackV1, and ScheduleSelectedV1. v0.4 widens the bounded worker model in place (see Contracts), adds the Task DAG and ParallelAggregateV1 contracts, and keeps the no-Cordis boundary.

dsh-orchestrator adds a deterministic pure dag.ts module (DAG construction, cycle rejection, level/topological ordering, independence check, disjoint ownership validation) and extends the worker path so the parallel fan-out admits and runs N bounded workers with per-worker route selection, consumes the v0.4a isolation seam for each worker's workspace, aggregates normalized Handoffs into a ParallelAggregateV1, and runs integrated-result verification. Root route selection remains under the existing Adaptive Scheduler seam.

The execution flow:

```text
root task
  -> decompose (declarative sub-task spec: objective, read/write sets, dependencies)
  -> Orchestrator DAG validation (pure): acyclic, disjoint write sets, bounded width/nodes, subagentMaxDepth 1
  -> per-ready-level: v0.4a seam creates one isolated workspace per worker
  -> per-worker schedule: Adaptive Scheduler selects route per capability request
  -> Orchestrator hard validation + BudgetController final admission (N workers bounded)
  -> parallel subagents.start('spawn') per worker, each constrained to its isolated workspace
  -> per-worker Handoff normalization
  -> v0.4a seam: diff-derived ownership enforcement + accepted-worker patch integration
  -> aggregate ParallelAggregateV1 + integrated-result verification
  -> dsh-plugin durable events per worker and aggregate
```

## Contracts

### Task DAG

```ts
interface TaskNodeV1 {
  readonly schemaVersion: 1
  readonly nodeId: string              // unique within the graph
  readonly objective: string
  readonly profile: CapabilityProfileV1
  readonly constraints: SchedulingConstraintsV1
  readonly readPaths: readonly string[]     // repository-relative read declarations
  readonly writePaths: readonly string[]    // repository-relative ownership declarations
  readonly dependsOn: readonly string[]     // nodeIds that must complete first
  readonly requiredTools: readonly string[]
}

interface TaskDagV1 {
  readonly schemaVersion: 1
  readonly rootTaskId: string
  readonly nodes: readonly TaskNodeV1[]
}
```

parseTaskDagV1(value) validates and freezes a TaskDagV1 with explicit bounds: MAX_DAG_NODES total nodes, MAX_DAG_LEVELS dependency levels, MAX_DAG_PATHS read/write paths per node, MAX_DAG_DEPS dependencies per node, bounded UTF-8 string/array sizes (reusing scheduling bounds), no duplicate nodeIds, no self-dependency, and only existing dependency references.

### Independence, ownership, and depth

```ts
type DagValidationIssueV1 =
  | { code: 'cycle'; nodeId: string }
  | { code: 'duplicate-node'; nodeId: string }
  | { code: 'missing-dependency'; nodeId: string; dependsOn: string }
  | { code: 'overlapping-access'; nodeA: string; nodeB: string; mode: 'ww' | 'wr' | 'rw' }
  | { code: 'write-outside-root'; nodeId: string; path: string }
  | { code: 'too-many-nodes'; count: number; limit: number }
  | { code: 'too-many-levels'; levelCount: number; limit: number }
  | { code: 'level-width-exceeded'; level: number; width: number; limit: number }

interface DagValidationV1 {
  readonly schemaVersion: 1
  readonly valid: boolean
  readonly issues: readonly DagValidationIssueV1[]   // deterministically ordered
  readonly levels: readonly (readonly string[])[],    // topological levels in dependency order
  readonly levelCount: number,                        // max dependency depth + 1; a graph with no edges has levelCount 1
}
```

validateTaskDagV1(dag, limits) returns a frozen DagValidationV1. A graph is valid only when: every node is unique and acyclic; every dependency exists; nodes in the same ready level have pairwise disjoint access — W/W, W/R, and R/W overlaps are rejected, R/R overlap is allowed; no write path escapes the deployment root; total nodes, level count, and ready-level width each fit their configured bounds. A node runs only if every dependency is completed and ownership-valid; otherwise it receives a synthetic bounded blocked result and consumes no worker budget. Dependency chains across levels are allowed; subagentMaxDepth = 1 means each spawned worker is a leaf that never recursively delegates — it is not a graph-depth limit.

### Path grammar

readPaths and writePaths use a deliberately small grammar: normalized POSIX repository-relative file paths or directory prefixes ending in /. No glob metacharacters, no . or .., drive roots, empty segments, NULs, or symlink traversal. Case-sensitive lexical containment after normalization; duplicate/overlapping entries within one node are rejected by the parser. The v0.4a seam consumes the same grammar for diff-derived enforcement.

### Widened worker model

SchedulingConstraintsV1.maxWorkers becomes a bounded integer 0..MAX_PARALLEL_WORKERS (exported constant MAX_PARALLEL_WORKERS = 8, distinct from any configured default — config continues to require explicit maxWorkers); ScheduleDecisionV1 is unchanged: each worker keeps mode single-worker, workerCount 1, and its own route. Parallel execution is an Orchestrator-level execution mode driven by the validated DAG, not a new ScheduleDecisionV1 mode; the Scheduler never emits a batch decision and cannot change the DAG, write sets, or worker count. The existing rejection logic for unconfigured providers, over-limit tokens, and empty routes is preserved. Parser guards and JSON schemas are updated only where maxWorkers/budget views widen; existing single-worker/direct fixtures/tests remain valid.

### Budgets

Two distinct limits exist: maxParallelWorkers (max ready-level width) and the existing cumulative session worker budget (budgets.maxWorkers). DAG validation checks both total node count (≤ cumulative budget) and max ready-level width (≤ maxParallelWorkers). Runtime admission adds an Orchestrator-only atomic admitFanout(workerCount, actionCount): it checks all counters and commits once or not at all, never exposing release/transaction to the Scheduler. A preflight DAG/ownership failure consumes no budget. A runtime ownership violation (detected after the worker ran, via v0.4a diff) does consume the admitted execution budget but blocks integration.

### ParallelAggregateV1

```ts
interface ParallelAggregateV1 {
  readonly schemaVersion: 1
  readonly fanoutId: string
  readonly nodeResults: readonly {
    readonly nodeId: string
    readonly requestId: string
    readonly childSessionId?: string
    readonly status: 'completed' | 'blocked' | 'failed' | 'ownership-violation'
    readonly handoff?: HandoffV1
  }[]     // ordered by deterministic node order; bounded by MAX_PARALLEL_WORKERS
  readonly aggregateStatus: 'completed' | 'blocked' | 'failed' | 'verification-failed'
  readonly verification?: readonly VerificationEvidenceV1[]
  readonly ownershipViolations: readonly { readonly nodeId: string; readonly path: string }[]
}
```

parseParallelAggregateV1(value) validates, bounds, and freezes the aggregate with a total UTF-8 payload cap and max child count. Aggregate status derivation is deterministic (any ownership violation or verification failure → non-completed). The aggregate is a strict internal/event contract, not a replacement for HandoffV1; a parent-visible projection to HandoffV1 is defined explicitly by the integration layer.

### Durable events

Existing per-worker events (schedule-selected target=worker, worker-requested, worker-finished) are preserved one per worker. v0.4 adds a bounded fanoutId and nodeId correlation field to each parallel worker event payload (compatible additive v1 extension) and one aggregate event dsh-plugin/parallel-finished carrying fanoutId, worker count, per-worker requestIds, aggregate status, ownership violations, and integrated verification outcome — no raw output, no transcript, bounded payload.

## Decision precedence

The Orchestrator owns DAG/ownership/aggregation decisions. Resource decisions keep the v0.3 scheduler precedence, applied per worker capability request; the Scheduler cannot change the DAG, write sets, or worker count beyond the validated DAG and budget. When the Scheduler is absent, the Profile fixed route is used per worker.

## Parallel execution model

- The DAG is created by a deployment-controlled entry point (trusted code or a strict bounded parser over a model-authored proposal); v0.4 defines the parser and validation, and the replay fixture supplies the DAG. No scheduling or budget action occurs before DAG validation.
- A fan-out runs only the ready nodes of one level; a level completes when every worker Handoff is normalized and recorded. subagentMaxDepth = 1; dependency levels are orchestrated by the root, never by recursive worker delegation.
- Each worker is a fresh subagents.start('spawn') child with subagentMaxDepth 1, frozen route, allow-only tool filter including targeted verification, and an isolated workspace provided by the v0.4a seam.
- Ownership enforcement is diff-derived and physical: after each worker completes, the v0.4a seam extracts the actual diff from that worker's isolated copy and compares it against the node's declared writePaths; any change outside ownership marks the node ownership-violation, and its changes are never integrated.
- Workers that fail, block, or produce invalid Handoffs do not abort healthy siblings; the aggregate reports each status and the Orchestrator decides continuation under budget. A node whose dependency failed/blocked/violated receives a synthetic blocked result and consumes no worker budget.
- Integrated-result verification runs once on the union of accepted worker integrations under a deployment-controlled parallelVerification policy naming exact configured commands/arguments (admission order, budget consumption, event order, and aggregate status mapping are defined by that policy); it is not left to ad-hoc working-tree state.

## v0.4a isolation seam (consumed, not implemented)

v0.4 depends on the v0.4a dsh-isolated-workspace seam with this contract (implemented in v0.4a, faked in v0.4 keyless replay):

```ts
interface IsolatedWorkspaceSeam {
  prepareLevel(levelNodes: readonly { nodeId: string; writePaths: readonly string[] }[]): Promise<PreparedLevelV1>   // N isolated copies under trusted root
  diffAndCheck(workerId: string, declaredWritePaths: readonly string[]): Promise<OwnershipCheckV1>   // actual diff vs declared ownership
  integrateAccepted(workerIds: readonly string[]): Promise<IntegrationResultV1>   // apply only accepted, ownership-valid changes
  disposeLevel(): Promise<void>
}
```

PreparedLevelV1, OwnershipCheckV1, and IntegrationResultV1 are bounded JSON contracts from v0.4a. In v0.4's keyless gate, a deterministic fake seam returns scripted isolated diffs so DAG/aggregation/event logic is tested without real filesystem/git operations. End-to-end physical isolation is verified in v0.4a's own gate.

## Safe degradation

- No Scheduler → per-worker Profile fixed route, deterministic and keyless.
- Scheduler invalid/out-of-bound decision → same validation failure and fallback policy as v0.3; never silently expands worker count or provider.
- v0.4a seam absent or failing → parallel fan-out fails closed before admission; no worker starts, no budget consumed, and the root degrades to the Single Worker path or reports the blocker under the existing handoff semantics.
- DAG invalid (cycle/overlap/too many) → reject fan-out before admission, record issue, no budget consumed.
- Ownership violation at runtime → execution budget remains consumed but integration is blocked and the node is marked ownership-violation.
- Provider auth/quota/rate-limit errors never trigger silent paid fallback.
- run-started keeps actual-route semantics.

## Evaluation and error handling

Keyless replay covers:

- DAG validation: valid acyclic graph, cycle rejection, missing dependency, overlapping W/W/W/R/R/W access, write-outside-root, too-many-nodes, too-many-levels, level-width-exceeded.
- Parallel fan-out admission: N workers within bound, atomic admitFanout rollback on partial failure, no child start before admission commits.
- Per-worker route selection (scheduler-present and profile-fallback).
- Per-worker Handoff normalization and ownership result from the v0.4a seam fake (diff-derived ownership check vs declared writePaths).
- ParallelAggregateV1 construction, status derivation, and bounded payload.
- Integrated-result verification under the parallelVerification policy.
- Event provenance: per-worker schedule-selected/worker-requested/worker-finished plus one aggregate parallel-finished; ordering and bounded payloads.
- Profile-fallback, invalid-decision, quota/timeout/cooldown, escalation, Direct actual-route, and read-only budget snapshot regressions remain green.

Missing optional services, invalid decisions, quota failures, and unknown provider/model values fail closed or degrade deterministically without provider access. Every timeout/cancellation path releases owned resources (including v0.4a workspaces via disposeLevel). The provider smoke command remains the exact keyless DISABLED check.

## Acceptance criteria

1. The Task DAG contracts and validator are pure, deterministic, bounded, and keyless; cycle/overlap/ownership/depth/width/node-count issues are rejected before admission with deterministic issue ordering.
2. Parallel fan-out runs N bounded workers with per-worker route selection, atomic fan-out admission, and no child start before admission commits.
3. Each worker emits the existing per-worker durable events with additive fanoutId/nodeId; one aggregate parallel-finished event carries bounded fan-out provenance and integrated verification outcome.
4. Ownership violations are diff-derived via the v0.4a seam and never integrated; preflight DAG/ownership failures consume no budget; runtime violations consume execution budget but block integration.
5. A node whose dependencies failed/blocked/violated receives a synthetic bounded blocked result and consumes no worker budget.
6. Direct, Single Worker, Handoff, budget, targeted verification, canonical events, Adaptive Scheduler, and keyless DISABLED smoke semantics remain intact.
7. profiles/v0.1 remains byte-for-byte unchanged; no v0.4 profile is added; the parallel path is validated by a keyless replay fixture over the v0.3-adaptive profile with the v0.4a seam fake.
8. A named test:v0.4 gate (scheduling contracts + DAG/parser + Orchestrator parallel + loader/profile + tests/replay) plus typecheck, build, provider-disabled check, and git diff --check all pass.
