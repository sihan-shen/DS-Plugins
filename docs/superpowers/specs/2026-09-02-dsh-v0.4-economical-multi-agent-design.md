# DSH v0.4 Economical Multi-Agent Design

## Goal

Extend the Orchestrator so it can decompose a root task into bounded, independent sub-tasks and run them as parallel Workers whose declared file ownership is enforced at the declaration layer (each worker's self-reported changedFiles must fall inside its declared writePaths; violations fail closed and are never aggregated), then aggregate their Handoffs and verify the integrated result — while preserving the keyless v0.3 safety boundary, deterministic replay, and the single-monorepo plugin ownership model. v0.4 introduces a declarative Task DAG and independence/ownership validation as deterministic pure logic in the Orchestrator, a bounded parallel-worker execution path, declaration-layer ownership enforcement, Handoff aggregation into a strict ParallelAggregateV1, and an integrated-result verification gate. Worker processes run in the shared working tree exactly as today's Single Worker path. Physical execution isolation and trusted write capture are deferred milestones (see Deferred isolation work). No new runtime plugin beyond the Orchestrator is created; the Adaptive Scheduler continues to own resource/affinity selection.

## Scope and non-goals

v0.4 covers: the contracts needed for bounded parallel workers and task graphs; a deterministic, replayable Task DAG representation with file-ownership sets and dependency edges; a parallel fan-out path; declaration-layer ownership enforcement (self-reported changedFiles validated against declared writePaths via the authoritative path grammar in dsh-scheduling-contracts); per-worker Handoff normalization plus a strict ParallelAggregateV1 result; integrated-result verification; and a deterministic keyless replay gate over the v0.3-adaptive profile with a test-only overlay. It does not implement filesystem isolation, per-worker execution cwd binding, trusted per-worker write capture, actual-diff containment, or transactional file integration — all deferred (see below). It does not implement learning-based decomposition, LLM Judge independence approval, mutable warm worker reuse across tasks, cross-session physical worker pooling, recursive worker delegation beyond subagentMaxDepth 1, or any provider/network/real coding-task acceptance. Context-locality/prefix-compatible reuse and all deferred v0.3 roadmap items (hysteresis, shadow Judge, quota adapters) are explicitly deferred beyond v0.4. It does not modify profiles/v0.1, the Direct or Single Worker semantics, HandoffV1 projection semantics, BudgetController admission exclusivity, or the run-started actual-route projection.

## Deferred isolation work (explicitly out of v0.4 scope)

Ownership is enforced at the declaration layer in v0.4: a worker's self-reported changedFiles must be contained by its declared writePaths. This detects a worker that reports an out-of-scope mutation, but it cannot detect a worker that mutates the shared tree without reporting it, and it cannot physically prevent writes. Three stronger mechanisms are deferred to future milestones gated on verified Harness capability (the pinned Harness 0.1.1-rc.2 SubagentStartRequest has no cwd/workspace field, in-process spawn inherits the parent cwd, and per-child fs write attribution is unverified):

1. Per-worker execution cwd binding: each spawned child's process cwd/fs root points at its own isolated copy. Requires a Harness upgrade or a DSH-owned custom subagent provider that stamps child session cwd; a compatibility spike must precede it.
2. Trusted per-worker write capture: an Orchestrator-side journal of actual writes derived from the Harness fs/write-intent and fs/edit-intent event gates, attributed per child session, so ownership can be checked against real writes rather than self-reports. Requires a spike proving child-session attribution.
3. Actual-diff containment and transactional integration over isolated copies. Depends on 1 or 2.

A one-page record of these deferred items is kept in docs/superpowers/specs/2026-09-02-dsh-v0.4a-isolated-workspace-design.md so the boundary and the future seam (prepare/diff/integrate over isolated workspaces) remain documented; no v0.4a implementation is planned in this cycle.

## Baseline and constraints

- Keep DeepSeek Harness pinned at 0.1.1-rc.2 until a separate compatibility review proves an upgrade.
- Preserve Direct mode, Single Worker mode, HandoffV1, plugin-owned budgets, targeted verification, canonical dsh-plugin/ events, and the keyless DISABLED provider smoke.
- The Orchestrator owns task DAG, independence/ownership validation, worker lifecycle, final budget admission, Handoff normalization/aggregation, and event recording. The Scheduler only provides capability-to-schedule decisions.
- Do not fork or modify upstream/deepseek-harness or replace its agent loop.
- All model-visible outputs and all orchestration evidence stay bounded, provenance-carrying, and safe to replay.
- No orchestration decision may bypass the Orchestrator's hard constraints (maxWorkers, maxPluginToolActions, tool allowlist, workspace/verification policy, disjoint ownership).
- Workers run in the shared working tree and self-report changedFiles. Declaration-layer ownership means: self-reported changedFiles outside declared writePaths fail closed (node invalid, not aggregated). Physical containment is not claimed in v0.4.
- Per-node TaskNodeV1 constraints may only NARROW the deployment limits. The effective capability request is a deterministic field-by-field intersection defined in the Constraints intersection table; required capabilities fail closed on empty intersection rather than silently disappearing.
- Unknown quota, price, or health values are never invented or silently estimated into hard routing decisions.
- No v0.4 profile is added. The parallel path is activated only through a validated test-only overlay over the v0.3-adaptive profile (loader-convention-compatible) plus replay fixtures in tests/replay. Real deployments enabling parallel mode are deferred until execution isolation exists.
- "Reload-safe" in this spec means same-process service-generation/HMR reload over a live session (persistence is write-behind in the pinned Harness); process-restart/crash durability is out of scope. When restart durability is later required, ctx.sessions.flush after parallel-started must be added.

## Architecture

The repository keeps the existing packages and adds no new runtime plugin:

```text
packages/
  dsh-scheduling-contracts/   # pure types, JSON schema, parsers; no Cordis runtime. Authority for DAG, aggregate, path grammar, bounds, and worker scheduling constraints
  dsh-orchestrator/           # gains task DAG, independence/ownership validation, parallel fan-out, declaration-layer ownership, aggregation, ParallelExecutionService
```

dsh-scheduling-contracts already defines CapabilityRequestV1, RouteDecisionV1, ScheduleDecisionV1, BudgetViewV1, ScheduleFeedbackV1, and ScheduleSelectedV1. v0.4 widens SchedulingConstraintsV1.maxWorkers and BudgetViewV1 bounds, adds the Task DAG, ParallelAggregateV1, ParallelVerificationPolicyV1, and the authoritative path grammar/types/bounds, and keeps the no-Cordis boundary. Worker-event types (WorkerSpecV1, WorkerFinishedV1) and their parsers/append helpers remain Orchestrator-local exactly as today; scheduling-contracts does NOT gain worker-event types or parsers.

dsh-orchestrator adds a deterministic pure dag.ts module (DAG parsing/validation, cycle rejection via SCC, level/topological ordering, independence check, disjoint ownership validation), a declaration-layer ownership check (changedFiles containment), a ParallelExecutionService seam, and extends the worker path so the parallel fan-out admits and runs N bounded workers with per-worker route selection, enforces declaration-layer ownership, aggregates normalized Handoffs into ParallelAggregateV1 emissions plus a cumulative DAG final aggregate, and runs integrated-result verification. Root route selection remains under the existing Adaptive Scheduler seam.

The execution flow:

```text
root task
  -> caller parses TaskDagV1 (parseTaskDagV1) then invokes ParallelExecutionService.run({ dag, parent, signal })   // Orchestrator-internal; only the test overlay invokes it; policy comes from config.parallel.verification
  -> run() validates the already-parsed DAG (validateTaskDagV1) and the strict request envelope (rejects unknown keys, incl. a stray policy key)
  -> per-ready-level: per-worker schedule (Adaptive Scheduler, unchanged ScheduleDecisionV1) -> hard validation -> BudgetController.admitFanout (atomic)
  -> parallel subagents.start('spawn') per worker in the shared working tree (same execution model as Single Worker)
  -> per-worker Handoff normalization (self-reported changedFiles)
  -> declaration-layer ownership check: changedFiles ⊆ declared writePaths (grammar containment); violation => node ownership-violation, not aggregated
  -> deterministic aggregate builder: one ParallelAggregateV1 emission per policy scope boundary, plus one cumulative scope-dag final aggregate
  -> dsh-plugin durable events per worker and per emitted aggregate
```

## Contracts

### Constants (authoritative, in dsh-scheduling-contracts)

MAX_PARALLEL_WORKERS = 8 (max ready-level width); MAX_DAG_NODES = 16 (total nodes in one DAG; the cumulative per-session worker budget ceiling); MAX_DAG_LEVELS = 4; MAX_DAG_PATHS = 32 per node (readPaths and writePaths each); MAX_DAG_DEPS = 8 per node; MAX_DAG_CHANGED_FILES = 16 (parallel-specific cap on the number of changedFiles the builder retains per node as sample paths); MAX_AGGREGATE_PAYLOAD_BYTES = 131072 (total UTF-8 serialized payload of one ParallelAggregateV1); MAX_AGGREGATE_VERIFICATION_TOTAL_BYTES = 49152 (total bytes for the verification evidence section of one aggregate); MAX_AGGREGATE_VERIFICATION_OUTPUT_BYTES = 8192 (combined stdout+stderr retained per command; per-command metadata/args are additionally bounded below); MAX_AGGREGATE_VIOLATION_BYTES = 24576 (total bytes for the ownership-violation summary section of one aggregate); MAX_AGGREGATE_PATH_BYTES = 1024 (per sample display path); MAX_AGGREGATE_PROJECTED_HANDOFF_BYTES = 24576 (total bytes for projectedHandoff, replacing any earlier handoff-bytes constant); MAX_VERIFICATION_COMMANDS = 4; MAX_VERIFICATION_ARGS = 8 (per parallel verification command, enforced at parseConfig); MAX_VERIFICATION_ARG_BYTES = 256 (per arg, enforced at parseConfig). Identifiers are bounded in UTF-8 bytes (see Identifier grammar). Each constant has exact-bound and one-over-bound tests. These are the ONLY aggregate-size authorities.

### Path grammar and identifiers

Authoritative in dsh-scheduling-contracts. RepoFilePath: canonical POSIX repository-relative path, no trailing slash. RepoDirectoryPrefix: ends in /. No glob metacharacters, no . or .., drive roots, empty segments, NULs, or backslash. Case-sensitive lexical containment: RepoDirectoryPrefix p/ contains path q when q starts with p/; RepoFilePath p contains only itself. No whole-repository sentinel. write-outside-root is not a pure-validator concern in v0.4: every grammar-valid path is lexically repository-relative, and any deployment subroot restriction is enforced by the declaration-layer ownership check against declared writePaths (the write set itself is the boundary). A normative containment examples table ships with the grammar.

Identifier grammar (all limits in UTF-8 bytes). The pinned Harness SessionId is a compile-time brand over an arbitrary string with no length/ASCII validation, and SubagentRun.id is a SessionId that remote providers may mint; therefore v0.4 does NOT assume a Harness-enforced ceiling. Instead the parallel service enforces its own compatibility grammar: the root session id actually used at run() time must be ASCII ≤ 48 bytes (rejected with a typed error otherwise), and dagId = <rootSessionId>:dag:<n> is then ≤ 48 + 5 + 3 = 56 bytes (n ≤ 999; see ordinal bound). nodeId: well-formed Unicode without lone surrogates, ≤ 32 UTF-8 bytes, no characters from {:, ", \, control chars}. Derived identifiers: requestId = dagId + ":node:" + nodeId ≤ 56 + 6 + 32 = 94 bytes; levelId = dagId + ":level:" + levelIndex ≤ 67 bytes; fanoutId = levelId for level scope, dagId + ":aggregate" for dag scope ≤ 67 bytes. workerId is the full SubagentRun.id string retained ONLY in the durable worker-finished event; the aggregate node result carries a derived bounded reference workerRef = "w:" + sha256(workerId).slice(0,16) (32 hex chars) instead of the unbounded raw id, so aggregate node results never exceed their byte budget regardless of the Harness id. All aggregate identifiers satisfy the existing 256-UTF-8-byte scheduling identifier ceiling by construction.

### Task DAG

```ts
interface TaskNodeV1 {
  readonly schemaVersion: 1
  readonly nodeId: string              // unique within the graph; identifier grammar above
  readonly objective: string
  readonly profile: CapabilityProfileV1
  readonly constraints: SchedulingConstraintsV1   // sole authority for requiredTools and per-node limits; may only narrow deployment limits
  readonly readPaths: readonly (RepoFilePath | RepoDirectoryPrefix)[]   // repository-relative read declarations
  readonly writePaths: readonly (RepoFilePath | RepoDirectoryPrefix)[]  // repository-relative ownership declarations
  readonly dependsOn: readonly string[]     // nodeIds that must complete first
}

interface TaskDagV1 {
  readonly schemaVersion: 1
  readonly rootTaskId: string
  readonly nodes: readonly TaskNodeV1[]   // length >= 1 (empty DAG is a structural TypeError)
}

interface DagValidationLimitsV1 {
  readonly schemaVersion: 1
  readonly maxNodes: number        // <= MAX_DAG_NODES; deployment/runtime limit, default MAX_DAG_NODES
  readonly maxLevels: number       // <= MAX_DAG_LEVELS; default MAX_DAG_LEVELS
  readonly maxWidth: number        // <= MAX_PARALLEL_WORKERS; default MAX_PARALLEL_WORKERS
  readonly maxCumulativeWorkers: number   // <= MAX_DAG_NODES; derived from the session cumulative worker budget (budgets.maxWorkers)
}
```

parseTaskDagV1(value) is strict and bounded: it validates JSON shape, path grammar, identifier grammar, per-field string/array bounds, empty-DAG rejection, and deep-freezes. It throws TypeError on structural violations only (invalid JSON shape, invalid path/identifier syntax, empty nodes, over-limit per-node arrays/strings, unknown fields). Duplicate nodeIds, self-dependency, unknown dependency references, cycle, overlap, and graph-wide limit violations are SEMANTIC issues returned by validateTaskDagV1, never thrown by the parser. validateTaskDagV1(dag: TaskDagV1, limits: DagValidationLimitsV1) accepts only already-parsed TaskDagV1 and returns DagValidationV1; valid === true only when issues is empty. Dependency chains across levels are allowed; subagentMaxDepth = 1 means each spawned worker is a leaf that never recursively delegates — it is not a graph-depth limit.

```ts
type DagValidationIssueV1 =
  | { code: 'duplicate-node'; nodeId: string }
  | { code: 'self-dependency'; nodeId: string }
  | { code: 'missing-dependency'; nodeId: string; dependsOn: string }
  | { code: 'cycle'; nodeId: string }
  | { code: 'overlapping-access'; nodeA: string; nodeB: string; mode: 'ww' | 'wr' | 'rw' }
  | { code: 'too-many-nodes'; count: number; limit: number }
  | { code: 'too-many-levels'; levelCount: number; limit: number }
  | { code: 'level-width-exceeded'; level: number; width: number; limit: number }
  | { code: 'cumulative-worker-limit-exceeded'; count: number; limit: number }

interface DagValidationV1 {
  readonly schemaVersion: 1
  readonly valid: boolean
  readonly issues: readonly DagValidationIssueV1[]   // deterministic order, see comparator below
  readonly levels: readonly (readonly string[])[]
  readonly levelCount: number                        // 0 when any cycle or malformed node blocks a full acyclic ordering; otherwise max dependency depth + 1; a non-empty graph with no edges has levelCount 1
}
```

Node eligibility before topological layering: duplicate-ID declarations are all omitted from levels (each duplicated id emits one duplicate-node issue); missing-dependency is emitted ONLY for direct references to a nodeId that does not exist (each direct missing reference emits one issue carrying its own dependsOn), and every node downstream of a missing reference — direct or transitive — is omitted WITHOUT additional missing-dependency issues (deterministic: a node reachable from multiple missing roots is omitted once and emits no extra issue); a self-dependent node emits exactly one self-dependency issue and is omitted (it does not additionally emit cycle); nodes in a non-trivial strongly connected component (SCC) each emit one cycle issue (all cycle issues ordered lexically by nodeId after rank) and are omitted along with every node downstream of the SCC. levels then contains each eligible unique node exactly once in topological order; when no eligible node remains, levels is empty and levelCount is 0. levelCount is 0 whenever any cycle or malformed-node exclusion occurred; otherwise max dependency depth + 1.

Deterministic issue ordering uses a per-code numeric rank in this order: duplicate-node(1), self-dependency(2), missing-dependency(3), cycle(4), overlapping-access(5), too-many-nodes(6), too-many-levels(7), level-width-exceeded(8), cumulative-worker-limit-exceeded(9), then a full comparator key per issue variant: (rank, nodeId, dependsOn) for missing-dependency; (rank, nodeId) for duplicate-node/self-dependency/cycle; (rank, nodeA, nodeB, mode) for overlapping-access with nodeA and nodeB canonicalized lexically; (rank, limit, count) for too-many-nodes/cumulative-worker-limit-exceeded; (rank, limit, levelCount) for too-many-levels; (rank, level, limit, width) for level-width-exceeded. overlapping-access carries no path.

Overlap generation: only nodes that may execute concurrently (nodes in the same ready level, i.e. not ordered by a dependency edge) are compared. For each unordered pair the read/write declarations are intersected under the grammar: a write-write, write-read, or read-write overlap on any path emits at most one issue per pair with mode precedence ww < wr < rw (the most severe present mode wins); nodeA/nodeB are canonicalized lexically. Sequential producer-consumer access across dependency-ordered levels is allowed and never emits overlap. An ownership violation blocks only dependent descendants; independent eligible branches in the same or later levels continue unless verification scope or budget stops the DAG.

### Constraints intersection (deployment ∩ node), field by field

The effective capability request per node is computed deterministically. Node constraints may only narrow deployment limits; each field's operation and empty-result behavior:

| Field | Operation | Empty / invalid result |
| --- | --- | --- |
| maxWorkers | ignored for fan-out width (width comes from the validated level, bounded by parallel.maxParallelWorkers); node maxWorkers 0 remains structurally valid and makes the node a scheduling-time blocked node with reason zero-worker-constraint (it never invalidates the DAG and no worker is admitted) | blocked node, no admission |
| maxOutputTokens | min(deployment fixed worker ceiling, node value) | n/a (min is total) |
| maxLatencyMs | min(deployment ceiling, node value) | n/a |
| allowPaidFallback | AND (deployment must allow and node must allow) | false → no paid fallback, deterministic |
| allowedProviders | intersection of deployment allowed routes' providers and node list; if empty → no catalog route, fail closed | fail closed: node blocked (reason no-route), no worker admitted |
| requiredTools | every node-required tool must be in the deployment worker-tool allowlist AND in the selected route's tool filter (scheduler catalog entry when the Scheduler is present; the configured route-to-tool-filter map when absent); otherwise fail closed | fail closed: node blocked (reason tool-unauthorized), no worker admitted |
| string/item/token ceilings | min with scheduling contract ceilings | n/a |

Empty intersections fail closed with the node reported blocked and a typed reason, never by silently dropping the requirement. Scheduler-absent tool authorization: the deployment parallel config owns a worker-tool allowlist and a route-to-tool-filter map (validated in parseConfig), so both the Scheduler-present and Scheduler-absent (fixed-route fallback) paths apply the same tool intersection; the worker allowlist (SubagentStartRequest.toolFilter) is exactly the effective requiredTools of the accepted route in both paths.

### Widened worker model, budgets, and parallel config

SchedulingConstraintsV1.maxWorkers becomes 0..MAX_PARALLEL_WORKERS (per-request worker width). ScheduleDecisionV1 is unchanged: each worker keeps mode single-worker, workerCount 1, and its own route. Parallel execution is an Orchestrator-level execution mode driven by the validated DAG; the Scheduler never emits a batch decision and cannot change the DAG, write sets, or worker count. Existing single-worker/direct fixtures/tests remain valid.

Two distinct limits exist, with distinct bounds:
- maxParallelWorkers (max ready-level width): 0..MAX_PARALLEL_WORKERS (8). This is parallel.maxParallelWorkers.
- budgets.maxWorkers (cumulative per-session worker budget) and every worker counter in BudgetViewV1: 0..MAX_DAG_NODES (16). This is the ceiling a whole multi-level DAG runs under.

DAG validation checks max ready-level width (≤ maxWidth), total node count (≤ maxCumulativeWorkers via cumulative-worker-limit-exceeded, and ≤ maxNodes via too-many-nodes). Runtime admission adds an Orchestrator-only atomic admitFanout(workerCount): accounting rule — one internal fan-out action charged to the existing delegate_worker plugin-action counter per executed level (the internal parallel service never invokes the model-facing delegate_worker tool; the counter is reused for accounting), N cumulative worker admissions, and one targeted_verify action per verification command actually run by the configured policy. Atomic algorithm: take a pre-admission snapshot, compute requested {workers: N, actions: 1}, and evaluate each counter's post-request slack = limit - (current + requested); if both would overflow, report the rejection with the more negative slack first (tie: worker rejection first); DISPOSED takes precedence over both; exactly one durable budget-rejected event is emitted for an atomic fan-out failure; commit all counters or none through a single internal atomic mutation path (never by composing the side-effecting scalar admit methods, which would double-record rejections). admitFanout is never exposed to the Scheduler. A preflight DAG/ownership failure consumes no budget. A runtime declaration-layer ownership violation consumes the admitted execution budget but blocks aggregation. When a level's admitFanout is rejected, every node of that level and all downstream nodes become not-run with reason admission-rejected, and the cumulative aggregate reports blocked (never completed).

Strict Orchestrator config gains an optional parallel block with this exact shape (added to types/parser under dsh-orchestrator):

```ts
interface ParallelConfigV1 {
  readonly maxParallelWorkers: number       // 0..min(MAX_PARALLEL_WORKERS, budgets.maxWorkers); no coupling to DAG shape
  readonly verification: ParallelVerificationPolicyV1
  readonly workerToolAllowlist: readonly string[]          // deployment-authorized worker tools (never includes targeted_verify)
  readonly routeToolFilters: Record<string, readonly string[]>   // route key -> tool filter, used by the Scheduler-absent fixed-route fallback
}
```

parseConfig accepts an optional top-level parallel key with only these fields. Conditional mode/budget semantics: without parallel, mode single-worker requires budgets.maxWorkers === 1 and mode direct requires budgets.maxWorkers === 0 exactly as today; with parallel, the model-facing delegate_worker under mode single-worker remains one-shot while the root controller may carry cumulative budgets.maxWorkers up to MAX_DAG_NODES for the internal parallel service, and mode direct remains incompatible with parallel (parseConfig rejects parallel alongside direct). A profile without parallel stays direct/single-worker exactly as today.

### Declaration-layer ownership

checkOwnership(changedFiles, writePaths): normalized via the grammar; valid iff every changedFile is contained by some writePath. Returns the sorted unique set of violating paths. A worker whose Handoff changedFiles contains any path outside its declared writePaths is marked ownership-violation; its Handoff is not aggregated and its changes are not reported as accepted. Because workers self-report changedFiles, this cannot detect unreported shared-tree mutations (deferred isolation work), and v0.4 never claims otherwise. The builder records, per ownership-violation node, the exact violation count and a sha256 digest commitment over a canonical byte preimage (see Ownership digest), plus up to MAX_DAG_CHANGED_FILES sample display paths.

### ParallelAggregateV1, builder/parser guarantees, and aggregate-size budget

```ts
type NodeOutcomeReasonV1 =
  | 'dependency-not-run'          // a dependency failed/blocked/violated
  | 'zero-worker-constraint'      // node constraints.maxWorkers === 0
  | 'no-route'                    // empty allowedProviders/route intersection
  | 'tool-unauthorized'           // required tool not in allowlist/route filter
  | 'admission-rejected'          // level admitFanout rejected
  | 'level-verification-failed'   // earlier level verification stopped the DAG
  | 'cancelled'                   // parent signal aborted before/during the run
  | 'start-failed'                // subagents.start rejected before a child published
  | 'completed'                   // ran to completion (only for status completed)
  | 'violation'                   // ownership-violation (only for status ownership-violation)
  | 'blocked-result'              // worker returned a blocked handoff
  | 'failed-result'               // worker returned a failed handoff

interface ParallelNodeResultV1 {
  readonly schemaVersion: 1
  readonly nodeId: string
  readonly requestId: string            // deterministic pre-admission invocation id; derived for every node including not-run
  readonly workerRef?: string           // "w:" + sha256(workerId).slice(0,16); present iff a child was successfully published (started); the full workerId lives only in the worker-finished event
  readonly status: 'completed' | 'blocked' | 'failed' | 'ownership-violation' | 'not-run'
  readonly reason: NodeOutcomeReasonV1  // typed, status-dependent (invariants below); enables payload-reconstructable aggregate status
}

interface OwnershipViolationSummaryV1 {
  readonly nodeId: string
  readonly count: number                          // exact violation count, 1..128 (a worker Handoff changedFiles allows up to 128 entries)
  readonly digest: string                         // sha256 hex over the canonical preimage of the sorted unique violating paths (collision-resistant)
  readonly samplePaths: readonly string[]         // sorted unique, length <= min(MAX_DAG_CHANGED_FILES, count), each <= MAX_AGGREGATE_PATH_BYTES
}

interface ParallelAggregateV1 {
  readonly schemaVersion: 1
  readonly dagId: string             // identifies the whole DAG run; durable across same-process service-generation reloads
  readonly scope: 'level' | 'dag'
  readonly fanoutId: string          // level scope: levelId; dag scope: dagId + ":aggregate"
  readonly levelId?: string          // present when scope === 'level'
  readonly levelIndex?: number       // deterministic 0-based level ordinal; present when scope === 'level'
  readonly nodeResults: readonly ParallelNodeResultV1[]   // unique nodeIds and requestIds; deterministic order (level then lexical nodeId); full Handoffs are NOT embedded (they live in worker-finished events and are referenced by requestId)
  readonly aggregateStatus: 'completed' | 'blocked' | 'failed' | 'verification-failed'
  readonly verification?: readonly VerificationEvidenceV1[]   // aggregate projections, bounded by MAX_AGGREGATE_VERIFICATION_TOTAL_BYTES; see Verification evidence projection
  readonly ownershipViolations: readonly OwnershipViolationSummaryV1[]   // per-node summaries; bounded by MAX_AGGREGATE_VIOLATION_BYTES
  readonly projectedHandoff: HandoffV1    // deterministic BOUNDED projection (never the full union); bounded by MAX_AGGREGATE_PROJECTED_HANDOFF_BYTES
  readonly projectedHandoffTruncated?: true   // set when the projection dropped content that the full union would have contained
}
```

Ownership digest preimage: sha256 over the UTF-8 bytes of JSON.stringify(sortedUniqueCanonicalPaths), where sortedUniqueCanonicalPaths is the sorted array of the node's canonical violating paths. Digest scope is per node (nodeId + digest), so two nodes with identical violating sets remain distinct. count is in 1..128 (never 0 for an ownership-violation node); samplePaths are sorted unique with samplePaths.length <= min(MAX_DAG_CHANGED_FILES, count); summaries are ordered lexically by nodeId.

Deterministic identifiers. dagId = <rootSessionId>:dag:<n> where rootSessionId is ASCII ≤ 48 bytes (enforced by the service at run() with a typed error otherwise) and n is a decimal ordinal 1..999 allocated synchronously before any admission; the service appends a bounded dsh-plugin/parallel-started event carrying dagId at allocation time (before any worker starts). Ordinal initialization scans the maximum ordinal across BOTH parallel-started and parallel-finished events for the root session in the live session log, so a same-process service-generation/HMR reload between allocation and aggregate emission cannot reuse an ordinal. Overlapping old/new service generations are serialized by requiring old-generation disposal before a replacement allocation (enforced by the service registry); allocation is synchronous under the service lock. workerRef = "w:" + sha256(workerId).slice(0,16) is derived from the full SubagentRun.id, which is retained only in the worker-finished event; workerRef is present iff a child was successfully published.

Status/reason invariants (parser-enforced): status completed ⇒ reason completed, workerRef present; status blocked ⇒ reason dependency-not-run, zero-worker-constraint, no-route, tool-unauthorized, blocked-result, or cancelled, with workerRef present only when a child was published (blocked-result or cancelled-after-start); status failed ⇒ reason start-failed, failed-result, or cancelled, with workerRef present only when a child was published; status ownership-violation ⇒ reason violation, workerRef present (the child ran and was rejected); status not-run ⇒ reason dependency-not-run, admission-rejected, level-verification-failed, zero-worker-constraint, no-route, tool-unauthorized, or cancelled-before-start, workerRef absent. Every started child has workerRef; pre-start failures and synthetic not-run have none.

Builder guarantees (producer): node order level-then-lexical; node results carry no embedded Handoffs (full Handoffs are emitted in worker-finished events and correlated by requestId); ownership-violation summaries are exact in count and digest with bounded samplePaths; projectedHandoff is a deterministic bounded projection (below); verification evidence is projected per command under the sub-budgets with derived truncated.

Aggregate-size budget (normative, serialized JSON bytes incl. keys, quotes, delimiters, escaping). One ParallelAggregateV1's serialized UTF-8 payload must be ≤ MAX_AGGREGATE_PAYLOAD_BYTES = 131072. The deterministic builder enforces these sub-budgets in fixed order over the exact serialized fragments; the values are the ONLY normative authority (no other arithmetic applies):
1. nodeResults + identifiers + envelope ≤ 16384 (16 nodes; each node result is small: nodeId ≤ 32 B, requestId ≤ 94 B, workerRef = 19 B or absent, status/reason ≤ 24 B, keys/escaping bounded; the builder caps a node result's serialized fragment at 1 KB worst case and stops adding once the section reaches 16384 — nodeResults is never truncated below the full node count because each fragment is small enough that 16 × 1 KB = 16384 fits);
2. verification evidence ≤ MAX_AGGREGATE_VERIFICATION_TOTAL_BYTES = 49152, with per-command combined stdout+stderr ≤ MAX_AGGREGATE_VERIFICATION_OUTPUT_BYTES = 8192 and per-command metadata (name + args) bounded by MAX_VERIFICATION_ARGS × MAX_VERIFICATION_ARG_BYTES + name ceiling (≤ 2 KB serialized); 4 × (2 KB metadata + 8192 output) = 40960 < 49152, so the section always fits with headroom for keys/escaping; deterministic truncation preserves bounded metadata for ALL records first, then allocates the remaining section budget to output in command order (see Verification evidence projection);
3. ownershipViolations summaries ≤ MAX_AGGREGATE_VIOLATION_BYTES = 24576; the builder retains count + digest for every violating node and adds samplePaths only while the section stays within budget; if samplePaths would exceed it, all samplePaths are dropped (count + digest preserve exactness); summary fragments are ordered lexically by nodeId;
4. projectedHandoff ≤ MAX_AGGREGATE_PROJECTED_HANDOFF_BYTES = 24576 (see projection rules; serialized-budget-aware, never count-only);
5. structural/rounding headroom ≤ 16384.
Sum: 16384 + 49152 + 24576 + 24576 + 16384 = 131072 exactly. The v0.4 gate includes a worst-case test using maximum identifiers, JSON-escapable characters (control chars, quotes, backslashes, 4-byte Unicode), maximum verification args/output, and maximum violation counts, asserting the serialized aggregate ≤ 131072 bytes and parses.

Verification evidence projection (deterministic): for each command in policy order, retain command name (bounded), args (bounded by the parseConfig-enforced MAX_VERIFICATION_ARGS × MAX_VERIFICATION_ARG_BYTES), exitCode, status, durationMs, and combined stdout+stderr output truncated so the per-command fragment ≤ 2 KB metadata + MAX_AGGREGATE_VERIFICATION_OUTPUT_BYTES output; truncated = source.truncated || stdoutWasCut || stderrWasCut. If the total verification section would exceed MAX_AGGREGATE_VERIFICATION_TOTAL_BYTES (it cannot under the per-command caps: 4 × (2 KB + 8 KB) = 40 KB < 49,152), the builder still enforces the section cap as a hard stop. Only stdout/stderr are shortened; name/args/exitCode/status/duration are preserved.

projectedHandoff projection rules (deterministic, serialized-budget-aware, always a valid HandoffV1 under the existing 128-item / 16 KB-string ceilings): the builder accumulates the full intended content (summary concatenation, lexically-deduplicated changed-file union, decisions union, blocker list, verification projections), then retains whole items in deterministic order (lexical for changedFiles/decisions/blockers; node order for summary) up to per-field serialized quotas that sum, with the Handoff envelope, to ≤ MAX_AGGREGATE_PROJECTED_HANDOFF_BYTES = 24576; per-field quotas: summary ≤ 4096 B, changedFiles ≤ 8192 B (whole items only), decisions ≤ 4096 B, blockers ≤ 4096 B, verification ≤ 2048 B, envelope/key overhead within the remainder. status maps from aggregateStatus (completed → completed; blocked → blocked; verification-failed → failed with the exact [verification: failed] marker; failed → failed). projectedHandoffTruncated is set whenever any field retained fewer whole items than the full intended content or the summary was cut (trailing [summary truncated] marker). Because item retention is whole-item and lexical, no path identity is ever corrupted by mid-string truncation.

Parser guarantees (parseParallelAggregateV1, enforced from the payload): nodeIds and requestIds unique; requestId present on every node; workerRef present iff a child was published (per status/reason invariants); status/reason pairs match the invariants table; ownershipViolations summaries reference only ownership-violation nodes, every ownership-violation node has exactly one summary with count in 1..128, and no other node has a summary; digests are 64-hex sha256; summaries ordered lexically by nodeId; scope 'level' has levelId/levelIndex and nodeResults bounded by MAX_PARALLEL_WORKERS; scope 'dag' has no levelId/levelIndex and nodeResults bounded by MAX_DAG_NODES; serialized UTF-8 payload ≤ MAX_AGGREGATE_PAYLOAD_BYTES; projectedHandoff is a parse-valid HandoffV1; aggregateStatus is recomputed from nodeResults + reason + verification state and must equal the stored value (payload-reconstructable). Exact recomputation of violation counts/digests from changedFiles is a builder guarantee, not a parser guarantee.

Aggregate status derivation (first match wins, exhaustive; derived from node statuses+reasons and verification state, never from projectedHandoff prose):
1. any node failed → failed;
2. any ownership-violation or blocked node → blocked;
3. any not-run node whose reason is admission-rejected or level-verification-failed (execution stopped before the full validated DAG ran) → blocked;
4. verification admission rejected (and no higher-precedence node outcome) → failed;
5. verification command failed (and no higher-precedence node outcome) → verification-failed;
6. nothing accepted (no completed-and-ownership-valid node) → blocked with an explanatory summary;
7. otherwise completed.

completed is reachable only when every node ran to completion (status completed, reason completed) and no verification issue occurred. Node outcomes (failed/blocked/ownership-violation) and execution-stopping not-run outrank verification admission rejection and verification command failure.

### DAG-wide final result

Level-scope execution emits one level aggregate per executed level (each also emits one parallel-finished event) AND one cumulative scope-dag final aggregate after the whole run (also emitted as a parallel-finished event). ParallelRunResultV1.aggregates contains every emission (level aggregates in level order, then the final DAG aggregate); finalAggregate is the cumulative scope-dag aggregate whose nodeResults contain every node of the DAG (level-scope node results merged in level-then-lexical order) and whose projectedHandoff is the parent-visible result. Level aggregates and the final cumulative aggregate are intermediate snapshots: they are non-additive for replay/telemetry — a replay consumer MUST reconstruct one final node set from the final scope-dag event, never concatenate node arrays across parallel-finished events (double-counting). Nodes skipped because a level-verification failure or admission rejection stopped execution are recorded as not-run with the typed reason (level-verification-failed / admission-rejected) in the final aggregate, and the final aggregate reports blocked per derivation step 3. DAG-scope execution emits exactly one scope-dag aggregate (and one parallel-finished event); aggregates = [finalAggregate].

### Durable events and compatibility

Existing per-worker events (schedule-selected target=worker, worker-requested, worker-finished) remain byte-compatible v1 payloads for non-parallel runs. Worker-event types (WorkerSpecV1, WorkerFinishedV1), their strict parsers, and append helpers stay Orchestrator-local exactly as today (scheduling-contracts does NOT own worker-event types/parsers). For parallel runs, v0.4 mandates one design (no fallback): optional fanoutId/nodeId/requestId correlation fields are added to the Orchestrator-local worker-requested/worker-finished append payloads AND to the schedule-selected event for parallel workers (as optional additive v1 fields: requestId + fanoutId; old payloads without them still parse; schedule-selected keeps its parser/schema updated to allow the optional fields). The replay join key for a worker is requestId (present on schedule-selected, worker-requested, worker-finished, and the node result); the full workerId and Handoff live in worker-finished. Event ordering per worker: schedule-selected(requestId) → worker-requested(requestId) → child start → worker-finished(requestId); per aggregate: parallel-finished after all its workers' worker-finished. Level-scope workers carry the level fanoutId; DAG-scope workers carry the DAG aggregate fanoutId. Old logs without the fields and new logs with them both parse; replay covers both shapes. schedule-selected for non-parallel runs remains exactly v0.3. One dsh-plugin/parallel-started event is appended synchronously at dagId allocation (before any worker starts) and carries dagId; one aggregate event dsh-plugin/parallel-finished is emitted per constructed ParallelAggregateV1 (including the cumulative final aggregate under level scope). The full per-worker Handoff remains in worker-finished (never embedded in the aggregate), so a replay consumer joins worker-finished by requestId to the aggregate node result.

### ParallelVerificationPolicyV1 and verification authority

```ts
interface ParallelVerificationPolicyV1 {
  readonly schemaVersion: 1
  readonly scope: 'level' | 'dag'     // 'level': verify after each executed level that produced accepted nodes; 'dag': verify once after all runnable levels
  readonly commands: readonly {
    readonly name: string
    readonly args: readonly string[]   // bounded by MAX_VERIFICATION_ARGS and MAX_VERIFICATION_ARG_BYTES (enforced at parseConfig)
  }[]   // ordered; bounded by MAX_VERIFICATION_COMMANDS
}
```

Sole verification authority. The deployment config's optional parallel.verification block is the ONLY source of the policy; ParallelExecutionService captures it at registration from its validated config and run() does NOT accept a policy argument, so a caller cannot bypass the validated command set. The pure contracts package provides parseParallelVerificationPolicyV1(value) for strict structural/bound checks only (shape, ordering, MAX_VERIFICATION_COMMANDS, string bounds, MAX_VERIFICATION_ARGS, MAX_VERIFICATION_ARG_BYTES). Command-existence and allowedArgs validation is Orchestrator config's job: validateParallelVerificationPolicy(policy, verificationConfig) checks every command name exists in the deployment's configured verification.commands and that every arg obeys the command's allowedArgs via the existing argument-policy validator; parseConfig runs it when the parallel block is present.

Semantics: an accepted node means the node completed with a valid, ownership-clean Handoff (independent of whether changedFiles is empty); verification runs at the policy scope when at least one accepted node exists. Scope 'level' verifies after each executed level with at least one accepted node; a verification failure prevents subsequent levels (remaining nodes become not-run with reason level-verification-failed). Scope 'dag' verifies once after all runnable levels and therefore cannot prevent earlier level execution. The Orchestrator admits each command directly through the root controller (one targeted_verify action per command) and invokes VerificationService without the model-facing tool wrapper. On admission rejection: exactly the controller's one budget-rejected event is emitted on the root session; the current command is not spawned and no later command runs; evidence from any earlier attempted commands in the same policy run is preserved in the aggregate; the aggregate maps per derivation step 4 with a fixed bounded blocker/summary marker [verification: budget-rejected] denoting a command that was not admitted (not that no command ran). Commands run in order; stop-on-first-failure maps the aggregate to verification-failed (derivation step 5) and emits verification-finished evidence per attempted command. Zero commands means no integrated verification runs. When no accepted node exists, verification is skipped and the aggregate reports blocked (derivation step 6). Parallel workers do NOT receive targeted_verify in their allowlists in v0.4 (worker-local verification is out of scope; integrated verification is the single verification authority for parallel runs).

Verification-with-partial-failure truth table (scope 'dag'; determines whether verification runs and the aggregate status; rows with not-run execution-stopping reasons resolve to blocked per derivation step 3):

| Node outcomes | Verification runs? | Aggregate status |
| --- | --- | --- |
| all completed-and-ownership-valid (changedFiles may be empty) | yes (accepted nodes exist) | verification-failed if a command fails, else completed |
| some accepted + some failed | yes | failed (node failed outranks) |
| some accepted + some blocked | yes | blocked (node blocked outranks) |
| some accepted + some ownership-violation | yes | blocked (violation outranks) |
| only not-run / no accepted node | no | blocked |
| accepted + later level admission-rejected (not-run) | (not reached for later level) | blocked (execution-stopping not-run) |
| accepted + no node failed/blocked/violation/stopped + verification admission rejected | yes, until the rejected command | failed ([verification: budget-rejected]) |
| accepted + node failed/blocked/violation + verification admission rejected | yes, until the rejected command | failed/blocked per node outcome (node outranks the rejection) |

## Runtime activation

v0.4 mandates exactly one activation seam. dsh-orchestrator exports an Orchestrator-internal ParallelExecutionService registered under the named Cordis service parallelExecution, with:

```ts
interface ParallelExecutionService {
  run(request: { dag: TaskDagV1; parent: Agent; signal: AbortSignal }): Promise<ParallelRunResultV1>
}

interface ParallelRunResultV1 {
  readonly dagId: string
  readonly aggregates: readonly ParallelAggregateV1[]   // level scope: per-executed-level aggregates in level order then the cumulative DAG aggregate; dag scope: exactly one DAG aggregate
  readonly finalAggregate: ParallelAggregateV1          // the cumulative scope-dag aggregate (parent-visible, covers all nodes)
}
```

run does not reparse dag (the caller passes an already-parsed TaskDagV1) but DOES strictly validate the request envelope: it rejects unknown keys (including a stray policy key) with a TypeError before any admission, and it enforces the root-session identifier compatibility grammar (ASCII ≤ 48 bytes) with a typed error otherwise. It validates against the deployment limits, allocates dagId (appending parallel-started), executes level by level under budget, enforces declaration-layer ownership, emits one ParallelAggregateV1 per policy scope boundary plus the cumulative DAG aggregate via the deterministic builder (each emission also emits one parallel-finished event), and returns ParallelRunResultV1 whose finalAggregate is the parent-visible result. Only the test-only overlay invokes run directly; there is no model-facing parallel tool and no new deployment mode. The overlay registers the service through the real Loader with the scripted subagent provider, proving the Loader — not direct construction — registered the parallel entry point. A profile without the optional parallel config never exposes the service.

## Decision precedence

The Orchestrator owns DAG/ownership/aggregation decisions. Resource decisions keep the v0.3 scheduler precedence, applied per worker capability request; the Scheduler cannot change the DAG, write sets, or worker count beyond the validated DAG and budget. When the Scheduler is absent, the Profile fixed route is used per worker with the configured route-to-tool-filter map. Node constraints narrow but never raise deployment limits.

## Parallel execution model

- The DAG is parsed by the caller, then submitted to ParallelExecutionService.run; the verification policy comes from config.parallel.verification (never a caller argument). No scheduling or budget action occurs before validation succeeds.
- run validates the root-session id, allocates dagId, and appends parallel-started before any worker starts. A fan-out runs only the ready nodes of one level; a level completes when every worker Handoff is normalized and recorded. subagentMaxDepth = 1; dependency levels are orchestrated by the root, never by recursive worker delegation. An ownership violation blocks only dependent descendants; independent eligible branches continue.
- Each worker is a fresh subagents.start('spawn') child with subagentMaxDepth 1, frozen route, and an allow-only tool filter equal to the effective requiredTools of the accepted route (sole tool authority, identical in scheduler and fixed-route fallback). Workers run in the shared working tree (same execution model as Single Worker) and self-report changedFiles; they do not receive targeted_verify.
- Declaration-layer ownership: after each worker completes, checkOwnership(changedFiles, writePaths) validates the self-reported changedFiles against declared ownership; any out-of-ownership path marks the node ownership-violation (reason violation, workerRef present) and its Handoff is not aggregated.
- Workers that fail, block, or produce invalid Handoffs do not abort healthy siblings; the aggregate reports each status with its typed reason. A node whose dependency failed/blocked/violated receives a synthetic not-run result (reason dependency-not-run, no workerRef) and consumes no worker budget. A node whose level admission was rejected or level verification failed is not-run with the typed reason.
- Integrated-result verification runs per the configured ParallelVerificationPolicyV1 scope when at least one accepted node exists, never redundantly per worker; a level-verification failure marks remaining nodes not-run with reason level-verification-failed.

## Safe degradation

- No Scheduler → per-worker Profile fixed route with the configured route-to-tool-filter map, deterministic and keyless.
- Scheduler invalid/out-of-bound decision → same validation failure and fallback policy as v0.3; never silently expands worker count or provider.
- DAG parse/validation failure → reject fan-out before admission, record issue, no budget consumed.
- Declaration-layer ownership violation at runtime → execution budget remains consumed but the node is marked ownership-violation (workerRef present) and its Handoff is not aggregated; only dependent descendants are blocked.
- Fan-out admission rejection at a level → that level's and downstream nodes become not-run (reason admission-rejected) and the cumulative aggregate reports blocked.
- Verification admission rejection → aggregate failed with the [verification: budget-rejected] marker when no higher-precedence node outcome exists; no further command runs; earlier command evidence preserved.
- Provider auth/quota/rate-limit errors never trigger silent paid fallback.
- run-started keeps actual-route semantics.

## Evaluation and error handling

Keyless replay covers:

- DAG parser rejections (invalid shape, bad path/identifier syntax, empty nodes, over-limit per-node arrays/strings, unknown fields) and validator semantic issues (duplicate node, self-dependency, direct-only missing dependency with deterministic transitive omission, cycle via SCC, W/W/W/R/R/W overlap on concurrent nodes only, too-many-nodes/levels, level-width-exceeded, cumulative-worker-limit-exceeded) with the full deterministic comparator and node-eligibility rules.
- Parallel fan-out admission: N workers within width and cumulative bounds, atomic admitFanout rollback on partial failure with exactly one budget-rejected event and deterministic rejection precedence, no child start before admission commits; admission rejection at a later level maps the cumulative aggregate to blocked.
- Per-worker route selection (scheduler-present and profile-fallback) with the field-by-field deployment∩node constraint intersection, the worker-tool allowlist, and fail-closed empty intersections producing typed not-run/blocked reasons.
- Declaration-layer ownership: checkOwnership containment; violation marked with reason violation and workerRef; in-ownership reports aggregated.
- ParallelAggregateV1 construction: builder guarantees (per-node count + sha256 digest over the JSON preimage, no embedded Handoffs) and parser guarantees (payload-visible invariants incl. status/reason table and payload-reconstructable aggregateStatus); the normative five-sub-budget size contract (worst case with JSON-escapable chars, max verification args/output, max violations ≤ 131072 bytes and parses); status truth table incl. execution-stopping not-run → blocked and verification admission rejection; deterministic identifiers (parallel-started-anchored, same-process-reload-safe, byte-bounded, workerRef derived); truncated derivation; serialized-budget-aware projectedHandoff with projectedHandoffTruncated.
- Integrated-result verification under the configured policy (scope level vs dag timing, accepted-node definition independent of changedFiles, ordering, action accounting, stop-on-first-failure, budget-rejection path with marker and preserved prior evidence, verification-finished evidence, zero-command and no-accepted-node cases, partial-failure truth table, workers without targeted_verify).
- Event provenance: parallel-started at allocation; per-worker schedule-selected/worker-requested/worker-finished with optional requestId/fanoutId correlation (old-without and new-with shapes), joinable by requestId (worker-finished Handoffs and full workerId rejoin to aggregate node results by workerRef/requestId); parallel-finished with cardinality equal to aggregate emissions; non-additivity rule for replay (reconstruct from the final scope-dag event only).
- Runtime activation: the test-only overlay boots through the real Loader, registers parallelExecution, run() rejects a stray policy key and an over-long/non-ASCII root session id at runtime, and asserts the composed scheduler catalog + route-tool-filter map route the intended keyless test tools and the captured SubagentStartRequest.toolFilter excludes targeted_verify.
- Identifier durability: parallel-started anchored ordinal survives a same-process reload; concurrent run() calls get distinct dagIds; long 4-byte-Unicode, reserved-character, control-character, and malformed node IDs are rejected by the grammar.
- Profile-fallback, invalid-decision, quota/timeout/cooldown, escalation, Direct actual-route, and read-only budget snapshot regressions remain green.

Missing optional services, invalid decisions, quota failures, and unknown provider/model values fail closed or degrade deterministically without provider access. Every timeout/cancellation path releases owned resources. The provider smoke command remains the exact keyless DISABLED check.
