# DSH v0.4 Economical Multi-Agent Design

## Goal

Extend the Orchestrator so it can decompose a root task into bounded, independent sub-tasks and run them as parallel Workers whose declared file ownership is enforced at the declaration layer (each worker's self-reported changedFiles must fall inside its declared writePaths; violations fail closed and are never aggregated), then aggregate their Handoffs and verify the integrated result — while preserving the keyless v0.3 safety boundary, deterministic replay, and the single-monorepo plugin ownership model. v0.4 introduces a declarative Task DAG and independence/ownership validation as deterministic pure logic in the Orchestrator, a bounded parallel-worker execution path, declaration-layer ownership enforcement, Handoff aggregation into a strict ParallelAggregateV1, and an integrated-result verification gate. Worker processes run in the shared working tree exactly as today's Single Worker path. Physical execution isolation and trusted write capture are deferred milestones (see Deferred isolation work). No new runtime plugin beyond the Orchestrator is created; the Adaptive Scheduler continues to own resource/affinity selection.

## Scope and non-goals

v0.4 covers: the contracts needed for bounded parallel workers and task graphs; a deterministic, replayable Task DAG representation with file-ownership sets and dependency edges; a parallel fan-out path; declaration-layer ownership enforcement (self-reported changedFiles validated against declared writePaths via the authoritative path grammar in dsh-scheduling-contracts); per-worker Handoff normalization plus a strict ParallelAggregateV1 result; integrated-result verification; and a deterministic keyless replay gate over the v0.3-adaptive profile with a test-only overlay. It does not implement filesystem isolation, per-worker execution cwd binding, trusted per-worker write capture, actual-diff containment, or transactional file integration — all deferred (see below). It does not implement learning-based decomposition, LLM Judge independence approval, mutable warm worker reuse across tasks, cross-session physical worker pooling, recursive worker delegation beyond subagentMaxDepth 1, or any provider/network/real coding-task acceptance. Context-locality/prefix-compatible reuse and all deferred v0.3 roadmap items (hysteresis, shadow Judge, quota adapters) are explicitly deferred beyond v0.4. It does not modify profiles/v0.1, the Direct or Single Worker semantics, HandoffV1 projection semantics, BudgetController admission exclusivity, or the run-started actual-route projection.

## Deferred isolation work (explicitly out of v0.4 scope)

Ownership is enforced at the declaration layer in v0.4: a worker's self-reported changedFiles must be contained by its declared writePaths. This detects a worker that honestly reports out-of-ownership changes, but it cannot detect a worker that mutates the shared tree without reporting it, and it cannot physically prevent writes. Three stronger mechanisms are deferred to future milestones gated on verified Harness capability (the pinned Harness 0.1.1-rc.2 SubagentStartRequest has no cwd/workspace field, in-process spawn inherits the parent cwd, and per-child fs write attribution is unverified):

1. Per-worker execution cwd binding: each spawned child's process cwd/fs root points at its own isolated copy. Requires a Harness upgrade or a DSH-owned custom subagent provider that stamps child session cwd; a compatibility spike must precede it.
2. Trusted per-worker write capture: an Orchestrator-side journal of actual writes derived from the Harness fs/write-intent and fs/edit-intent event gates, attributed per child session, so ownership can be checked against real writes rather than self-reports. Requires a spike proving child-session attribution.
3. Actual-diff containment and transactional integration over isolated copies. Depends on 1 or 2.

A one-page record of these deferred items is kept in docs/superpowers/specs/2026-09-02-dsh-v0.4a-isolated-workspace-design.md so the boundary and the future seam (prepare/diff/integrate over isolated workspaces) remain documented; no v0.4a implementation is planned in this cycle.

## Baseline and constraints

- Keep DeepSeek Harness pinned at 0.1.1-rc.2 until a separate compatibility review proves an upgrade.
- Preserve Direct mode, Single Worker mode, HandoffV1, plugin-owned budgets, targeted verification, canonical dsh-plugin/ events, and the keyless DISABLED provider smoke.
- The Orchestrator owns task DAG, independence/ownership validation, worker lifecycle, final budget admission, Handoff normalization/aggregation, and event recording. The Scheduler only provides capability-to-schedule decisions.
- Do not fork or modify upstream/deepseek-harness or replace its agent loop.
- All model-visible outputs and all orchestration evidence stay bounded, provenance-carrying, and safe to replay.
- No orchestration decision may bypass the Orchestrator's hard constraints (maxWorkers, maxPluginToolActions, tool allowlist, workspace/verification policy, disjoint ownership).
- Workers run in the shared working tree and self-report changedFiles. Declaration-layer ownership means: self-reported changedFiles outside declared writePaths fail closed (node invalid, not aggregated). Physical containment is not claimed in v0.4.
- Unknown quota, price, or health values are never invented or silently estimated into hard routing decisions.
- No v0.4 profile is added. The parallel path is activated only through a validated test-only overlay over the v0.3-adaptive profile (loader-convention-compatible) plus replay fixtures in tests/replay. Real deployments enabling parallel mode are deferred until execution isolation exists.

## Architecture

The repository keeps the existing packages and adds no new runtime plugin:

```text
packages/
  dsh-scheduling-contracts/   # pure types, JSON schema, parsers; no Cordis runtime. Authority for worker model, DAG, aggregate, path grammar, and bounds
  dsh-orchestrator/           # gains task DAG, independence/ownership validation, parallel fan-out, declaration-layer ownership, aggregation
```

dsh-scheduling-contracts already defines CapabilityRequestV1, RouteDecisionV1, ScheduleDecisionV1, BudgetViewV1, ScheduleFeedbackV1, and ScheduleSelectedV1. v0.4 widens SchedulingConstraintsV1.maxWorkers and BudgetViewV1 bounds, adds the Task DAG, ParallelAggregateV1, ParallelVerificationPolicyV1, and the authoritative path grammar/types/bounds, and keeps the no-Cordis boundary.

dsh-orchestrator adds a deterministic pure dag.ts module (DAG parsing/validation, cycle rejection, level/topological ordering, independence check, disjoint ownership validation) and a declaration-layer ownership check (changedFiles containment), and extends the worker path so the parallel fan-out admits and runs N bounded workers with per-worker route selection, enforces declaration-layer ownership, aggregates normalized Handoffs into a ParallelAggregateV1, and runs integrated-result verification. Root route selection remains under the existing Adaptive Scheduler seam.

The execution flow:

```text
root task
  -> DAG submission API (deployment-controlled; validated test overlay or trusted code supplies a TaskDagV1)
  -> parseTaskDagV1 (strict, bounded) + validateTaskDagV1 (semantic): acyclic, disjoint ownership, bounded nodes/levels/width, subagentMaxDepth 1
  -> per-ready-level: per-worker schedule (Adaptive Scheduler, unchanged ScheduleDecisionV1) -> hard validation -> BudgetController.admitFanout (atomic)
  -> parallel subagents.start('spawn') per worker in the shared working tree (same execution model as Single Worker)
  -> per-worker Handoff normalization (self-reported changedFiles)
  -> declaration-layer ownership check: changedFiles ⊆ declared writePaths (grammar containment); violation => node invalid, not aggregated
  -> aggregate ParallelAggregateV1 + integrated-result verification (parallelVerification policy)
  -> dsh-plugin durable events per worker and aggregate
```

## Contracts

### Constants (authoritative, in dsh-scheduling-contracts)

MAX_PARALLEL_WORKERS = 8 (max ready-level width; distinct from any configured default — config requires explicit maxWorkers); MAX_DAG_NODES = 16 (total nodes); MAX_DAG_LEVELS = 4; MAX_DAG_PATHS = 32 per node (readPaths and writePaths each); MAX_DAG_DEPS = 8 per node; MAX_AGGREGATE_PAYLOAD_BYTES = 65536 (total UTF-8 payload); MAX_VERIFICATION_COMMANDS = 4 (per parallelVerification policy). All string/array bounds reuse the existing scheduling/handoff byte and item ceilings. Each constant has exact-bound and one-over-bound tests.

### Path grammar

Authoritative in dsh-scheduling-contracts. RepoFilePath: canonical POSIX repository-relative path, no trailing slash. RepoDirectoryPrefix: ends in /. No glob metacharacters, no . or .., drive roots, empty segments, NULs, or backslash. Case-sensitive lexical containment: RepoDirectoryPrefix p/ contains path q when q starts with p/; RepoFilePath p contains only itself. No whole-repository sentinel. write-outside-root is not a pure-validator concern in v0.4: every grammar-valid path is lexically repository-relative, and any deployment subroot restriction is enforced by the declaration-layer ownership check against declared writePaths (the write set itself is the boundary). A normative containment examples table ships with the grammar.

### Task DAG

```ts
interface TaskNodeV1 {
  readonly schemaVersion: 1
  readonly nodeId: string              // unique within the graph
  readonly objective: string
  readonly profile: CapabilityProfileV1
  readonly constraints: SchedulingConstraintsV1
  readonly readPaths: readonly (RepoFilePath | RepoDirectoryPrefix)[]   // repository-relative read declarations
  readonly writePaths: readonly (RepoFilePath | RepoDirectoryPrefix)[]  // repository-relative ownership declarations
  readonly dependsOn: readonly string[]     // nodeIds that must complete first
  readonly requiredTools: readonly string[]
}

interface TaskDagV1 {
  readonly schemaVersion: 1
  readonly rootTaskId: string
  readonly nodes: readonly TaskNodeV1[]
}
```

parseTaskDagV1(value) is strict and bounded: it validates JSON shape, path grammar, per-field string/array bounds, and deep-freezes. It throws TypeError on structural violations (invalid JSON shape, invalid path syntax, over-limit strings/arrays). validateTaskDagV1(dag: TaskDagV1, limits) accepts only already-parsed TaskDagV1 and returns semantic issues (never throws): duplicate nodeId, self-dependency, missing-dependency reference, same-level W/W + W/R + R/W overlap (R/R allowed), too-many-nodes, too-many-levels, level-width-exceeded. valid === true only when issues is empty. Dependency chains across levels are allowed; subagentMaxDepth = 1 means each spawned worker is a leaf that never recursively delegates — it is not a graph-depth limit.

```ts
type DagValidationIssueV1 =
  | { code: 'duplicate-node'; nodeId: string }
  | { code: 'self-dependency'; nodeId: string }
  | { code: 'missing-dependency'; nodeId: string; dependsOn: string }
  | { code: 'cycle'; nodeId: string }
  | { code: 'overlapping-access'; nodeA: string; nodeB: string; mode: 'ww' | 'wr' | 'rw' }
  | { code: 'too-many-nodes'; count: number; limit: number }
  | { code: 'too-many-levels'; levelCount: number; limit: number }
  | { code: 'level-width-exceeded'; level: number; width: number; limit: number }

interface DagValidationV1 {
  readonly schemaVersion: 1
  readonly valid: boolean
  readonly issues: readonly DagValidationIssueV1[]   // deterministic order: issue-category rank, then lexical nodeId/path
  readonly levels: readonly (readonly string[])[]
  readonly levelCount: number                        // max dependency depth + 1; a graph with no edges has levelCount 1
}
```

Deterministic issue ordering uses an issue-category rank (duplicate-node, self-dependency, missing-dependency, cycle, overlapping-access, too-many-*, level-width-exceeded), then lexical nodeId and path — valid for invalid graphs because it does not depend on topological levels. When a cycle exists, levels contains only the acyclic schedulable nodes and the cyclic nodes are reported via cycle issues; when no acyclic ordering exists at all, levels is empty.

### Widened worker model and budgets

SchedulingConstraintsV1.maxWorkers becomes 0..MAX_PARALLEL_WORKERS; BudgetViewV1 counters widen to the same bound. ScheduleDecisionV1 is unchanged: each worker keeps mode single-worker, workerCount 1, and its own route. Parallel execution is an Orchestrator-level execution mode driven by the validated DAG; the Scheduler never emits a batch decision and cannot change the DAG, write sets, or worker count. Existing single-worker/direct fixtures/tests remain valid.

Two distinct limits exist: maxParallelWorkers (max ready-level width) and the existing cumulative session worker budget (budgets.maxWorkers). DAG validation checks total node count (≤ cumulative budget) and max ready-level width (≤ maxParallelWorkers). Runtime admission adds an Orchestrator-only atomic admitFanout(workerCount): accounting rule — one delegate_worker plugin action per accepted DAG-level invocation (the root delegation), N cumulative worker admissions, and one targeted_verify action per verification command actually run by the parallelVerification policy. Atomic algorithm: take a pre-admission snapshot, compute requested {workers: N, actions: 1}, evaluate each counter with post-request slack; if both would overflow, report the rejection with the smaller post-request slack first (tie: worker rejection first); DISPOSED takes precedence over both; exactly one durable budget-rejected event is emitted for an atomic fan-out failure; commit all counters or none. admitFanout is never exposed to the Scheduler. A preflight DAG/ownership failure consumes no budget. A runtime declaration-layer ownership violation (detected after the worker ran) consumes the admitted execution budget but blocks aggregation.

### Declaration-layer ownership

checkOwnership(changedFiles, writePaths): normalized via the grammar; valid iff every changedFile is contained by some writePath. A worker whose Handoff changedFiles contains any path outside its declared writePaths is marked ownership-violation; its Handoff is not aggregated and its changes are not reported as accepted. Because workers self-report changedFiles, this cannot detect unreported shared-tree mutations (deferred isolation work), and v0.4 never claims otherwise.

### ParallelAggregateV1

```ts
interface ParallelAggregateV1 {
  readonly schemaVersion: 1
  readonly fanoutId: string
  readonly scope: 'level' | 'dag'
  readonly levelId?: string
  readonly nodeResults: readonly {
    readonly nodeId: string
    readonly requestId: string
    readonly workerId?: string
    readonly status: 'completed' | 'blocked' | 'failed' | 'ownership-violation' | 'not-run'
    readonly handoff?: HandoffV1
  }[]     // unique nodeIds and requestIds; deterministic order
  readonly aggregateStatus: 'completed' | 'blocked' | 'failed' | 'verification-failed'
  readonly verification?: readonly VerificationEvidenceV1[]
  readonly ownershipViolations: readonly { readonly nodeId: string; readonly path: string }[]
  readonly projectedHandoff: HandoffV1    // explicit parent-visible projection, always present
}
```

Invariants enforced by parseParallelAggregateV1: nodeIds and requestIds unique; completed/blocked/failed nodes carry a handoff; ownership-violation and not-run nodes carry none; ownershipViolations exactly matches ownership-violation node results (an integration-conflict concept does not exist in v0.4 because integration is declaration-layer only); scope 'level' has levelId and nodeResults bounded by MAX_PARALLEL_WORKERS; scope 'dag' has no levelId and nodeResults bounded by MAX_DAG_NODES (one aggregate after all levels). MAX_AGGREGATE_PAYLOAD_BYTES caps total payload. Status precedence (lowest wins for non-completed): verification-failed > failed > ownership-violation > blocked > completed; a single ownership-violation forces non-completed. Verification is forbidden when no node was completed-and-ownership-valid (nothing accepted), and the aggregate then reports blocked with an explanatory summary. projectedHandoff is the deterministic HandoffV1 projection: status maps from aggregateStatus (completed → completed; blocked → blocked; verification-failed → failed with the exact [verification: failed] marker; failed → failed); summary concatenates accepted node summaries (bounded); changedFiles is the union of accepted (ownership-valid, completed) node changedFiles (bounded); verification carries the integrated evidence; blockers carry ownership violations and blocked/failed node summaries (bounded).

### Durable events and compatibility

Existing per-worker events (schedule-selected target=worker, worker-requested, worker-finished) remain byte-compatible v1 payloads for non-parallel runs. For parallel runs, v0.4 mandates one design (no fallback): optional fanoutId/nodeId correlation fields are added to worker-requested and worker-finished as part of the v1 type/parser/schema definitions; the updated types, parsers, schemas, and append-helper projections are owned and exported by dsh-scheduling-contracts (worker events) and dsh-orchestrator (append helpers). Old logs without the fields and new logs with them both parse; replay covers both shapes. schedule-selected remains exactly as v0.3 (no field added). One new aggregate event dsh-plugin/parallel-finished carries the bounded ParallelAggregateV1 projection (fanoutId, scope, per-worker requestIds/nodeIds/statuses, ownershipViolations, aggregateStatus, integrated verification outcome — no raw output, no transcript).

### ParallelVerificationPolicyV1

```ts
interface ParallelVerificationPolicyV1 {
  readonly schemaVersion: 1
  readonly scope: 'level' | 'dag'     // when verification runs: after each level, or once after the whole DAG
  readonly commands: readonly {
    readonly name: string
    readonly args: readonly string[]
  }[]   // ordered; bounded by MAX_VERIFICATION_COMMANDS
}
```

parseParallelVerificationPolicyV1 validates that every command name exists in the deployment's configured verification.commands and that args obey the command's allowedArgs. Semantics: commands run in order at the policy scope boundary; each consumes one targeted_verify plugin action admitted before spawn; stop-on-first-failure maps the aggregate to verification-failed, emits verification-finished evidence per attempted command, and stops later DAG levels when scope is 'dag'; zero commands means no integrated verification runs; when nothing was accepted, verification is skipped and the aggregate reports blocked. Parallel workers do NOT receive targeted_verify in their allowlists in v0.4 (worker-local verification is out of scope; integrated verification is the single verification authority for parallel runs). The policy is supplied by the test-only overlay or trusted deployment config (added to strict Orchestrator config parsing as an optional parallel block).

## Decision precedence

The Orchestrator owns DAG/ownership/aggregation decisions. Resource decisions keep the v0.3 scheduler precedence, applied per worker capability request; the Scheduler cannot change the DAG, write sets, or worker count beyond the validated DAG and budget. When the Scheduler is absent, the Profile fixed route is used per worker.

## Parallel execution model

- The DAG is submitted through a deployment-controlled entry point: a trusted-code API or a strict bounded parser over a model-authored proposal. v0.4 defines parseTaskDagV1 + validateTaskDagV1; the replay fixture supplies the DAG. No scheduling or budget action occurs before parsing and validation succeed.
- A fan-out runs only the ready nodes of one level; a level completes when every worker Handoff is normalized and recorded. subagentMaxDepth = 1; dependency levels are orchestrated by the root, never by recursive worker delegation.
- Each worker is a fresh subagents.start('spawn') child with subagentMaxDepth 1, frozen route, and an allow-only tool filter. Workers run in the shared working tree (same execution model as Single Worker) and self-report changedFiles; they do not receive targeted_verify (integrated verification is the single authority for parallel runs).
- Declaration-layer ownership: after each worker completes, checkOwnership(changedFiles, writePaths) validates the self-reported changedFiles against declared ownership; any out-of-ownership path marks the node ownership-violation and its Handoff is not aggregated.
- Workers that fail, block, or produce invalid Handoffs do not abort healthy siblings; the aggregate reports each status. A node whose dependency failed/blocked/violated receives a synthetic not-run result (no Handoff) and consumes no worker budget; the dependency blocker appears in projectedHandoff.blockers.
- Integrated-result verification runs per the ParallelVerificationPolicyV1 scope on the accepted (ownership-valid, completed) node changes, never redundantly per worker.

## Safe degradation

- No Scheduler → per-worker Profile fixed route, deterministic and keyless.
- Scheduler invalid/out-of-bound decision → same validation failure and fallback policy as v0.3; never silently expands worker count or provider.
- DAG parse/validation failure → reject fan-out before admission, record issue, no budget consumed.
- Declaration-layer ownership violation at runtime → execution budget remains consumed but the node is marked ownership-violation and its Handoff is not aggregated.
- Provider auth/quota/rate-limit errors never trigger silent paid fallback.
- run-started keeps actual-route semantics.

## Evaluation and error handling

Keyless replay covers:

- DAG parser rejections (invalid shape, bad path, over-limit) and validator semantic issues (duplicate node, self-dependency, missing dependency, cycle, W/W/W/R/R/W overlap, too-many-nodes/levels, level-width-exceeded) with deterministic issue ordering that does not depend on topological levels.
- Parallel fan-out admission: N workers within bound, atomic admitFanout rollback on partial failure with exactly one budget-rejected event and deterministic rejection precedence, no child start before admission commits.
- Per-worker route selection (scheduler-present and profile-fallback).
- Declaration-layer ownership: checkOwnership containment, a worker self-reporting an out-of-ownership path marked ownership-violation and not aggregated; a worker self-reporting only in-ownership paths aggregated.
- ParallelAggregateV1 construction, invariant enforcement, status precedence, and projectedHandoff mapping.
- Integrated-result verification under ParallelVerificationPolicyV1 (scope level vs dag, ordering, action accounting, stop-on-first-failure, verification-finished evidence, zero-command and nothing-accepted cases, workers without targeted_verify).
- Event provenance: per-worker schedule-selected/worker-requested/worker-finished (both with and without optional correlation fields) plus one aggregate parallel-finished; ordering and bounded payloads.
- Profile-fallback, invalid-decision, quota/timeout/cooldown, escalation, Direct actual-route, and read-only budget snapshot regressions remain green.

Missing optional services, invalid decisions, quota failures, and unknown provider/model values fail closed or degrade deterministically without provider access. Every timeout/cancellation path releases owned resources. The provider smoke command remains the exact keyless DISABLED check.

## Acceptance criteria

1. parseTaskDagV1/validateTaskDagV1 are pure, deterministic, bounded, keyless, and reject every listed condition before admission with deterministic ordering.
2. Parallel fan-out runs N bounded workers with per-worker route selection, atomic admitFanout (defined accounting, deterministic rejection precedence, one rejection event), and no child start before admission commits.
3. Per-worker durable events carry optional correlation fields that parse in both old-without and new-with shapes; one aggregate parallel-finished event carries bounded provenance and integrated verification outcome.
4. Declaration-layer ownership: a worker self-reporting out-of-ownership changedFiles is marked ownership-violation and not aggregated; in-ownership reports aggregate. v0.4 claims only declaration-layer enforcement.
5. A node whose dependencies failed/blocked/violated receives a synthetic not-run result (no Handoff) and consumes no worker budget.
6. ParallelAggregateV1 invariants, status precedence, and projectedHandoff are deterministic and tested; verification is skipped when nothing was accepted; parallel workers do not receive targeted_verify.
7. Direct, Single Worker, Handoff, budget, targeted verification, canonical events, Adaptive Scheduler, and keyless DISABLED smoke semantics remain intact.
8. profiles/v0.1 remains byte-for-byte unchanged; no v0.4 profile is added; the parallel path is validated by a loader-convention-compatible test-only overlay over the v0.3-adaptive profile.
9. A named test:v0.4 gate (scheduling contracts + DAG/parser + Orchestrator parallel + loader/profile + tests/replay) plus typecheck, build, provider-disabled check, and git diff --check all pass.
