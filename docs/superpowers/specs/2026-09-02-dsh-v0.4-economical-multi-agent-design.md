# DSH v0.4 Economical Multi-Agent Design

## Goal

Extend the Orchestrator so it can decompose a root task into bounded, independent sub-tasks and run them as parallel Workers whose declared file ownership is validated against actual diffs, then aggregate their Handoffs and verify the integrated result — while preserving the keyless v0.3 safety boundary, deterministic replay, and the single-monorepo plugin ownership model. v0.4 introduces a declarative Task DAG and independence/ownership validation as deterministic pure logic in the Orchestrator, a bounded parallel-worker execution path, diff-derived ownership enforcement via the v0.4a isolation seam, Handoff aggregation into a strict ParallelAggregateV1, and an integrated-result verification gate. Worker processes run in the shared working tree exactly as today's Single Worker path; per-worker execution cwd isolation is deferred (see v0.4a). No new runtime plugin beyond the Orchestrator is created; the Adaptive Scheduler continues to own resource/affinity selection.

## Scope and non-goals

v0.4 covers: the contracts needed for bounded parallel workers and task graphs; a deterministic, replayable Task DAG representation with file-ownership sets and dependency edges; a parallel fan-out path that consumes the v0.4a isolation seam (each worker self-reports changedFiles; v0.4a diff-checks the actual isolated copy against declared ownership; only ownership-valid changes are integrated); per-worker Handoff normalization plus a strict ParallelAggregateV1 result; integrated-result verification; and a deterministic keyless replay gate over the v0.3-adaptive profile with a test-only overlay and the v0.4a seam fake. It does not implement filesystem isolation internals (v0.4a), per-worker process cwd binding (deferred), learning-based decomposition, LLM Judge independence approval, mutable warm worker reuse across tasks, cross-session physical worker pooling, recursive worker delegation beyond subagentMaxDepth 1, or any provider/network/real coding-task acceptance. Context-locality/prefix-compatible reuse and all deferred v0.3 roadmap items (hysteresis, shadow Judge, quota adapters) are explicitly deferred beyond v0.4. It does not modify profiles/v0.1, the Direct or Single Worker semantics, HandoffV1 projection semantics, BudgetController admission exclusivity, or the run-started actual-route projection.

## Baseline and constraints

- Keep DeepSeek Harness pinned at 0.1.1-rc.2 until a separate compatibility review proves an upgrade.
- Preserve Direct mode, Single Worker mode, HandoffV1, plugin-owned budgets, targeted verification, canonical dsh-plugin/ events, and the keyless DISABLED provider smoke.
- The Orchestrator owns task DAG, independence/ownership validation, worker lifecycle, final budget admission, Handoff normalization/aggregation, and event recording. The Scheduler only provides capability-to-schedule decisions. The v0.4a isolation seam is injected and never owns orchestration state.
- Do not fork or modify upstream/deepseek-harness or replace its agent loop.
- All model-visible outputs and all orchestration evidence stay bounded, provenance-carrying, and safe to replay.
- No orchestration decision may bypass the Orchestrator's hard constraints (maxWorkers, maxPluginToolActions, tool allowlist, workspace/verification policy, disjoint ownership).
- Workers run in the shared working tree and self-report changedFiles; physical containment of a running worker's writes is NOT claimed in v0.4 (deferred). Ownership enforcement is diff-derived after the fact: a mutation outside declared ownership is detected against the worker's isolated copy and never integrated.
- Unknown quota, price, or health values are never invented or silently estimated into hard routing decisions.
- No v0.4 profile is added. The parallel path is activated only through a validated test-only overlay over the v0.3-adaptive profile (loader-convention-compatible) plus the v0.4a seam fake in tests/replay. Real deployments enabling parallel mode are deferred until execution isolation exists.

## Architecture

The repository keeps the existing packages and adds no new runtime plugin. v0.4 extends the Orchestrator-owned DAG/ownership/parallel layer and the pure contracts package; v0.4a (separate spec) supplies the isolation seam:

```text
packages/
  dsh-scheduling-contracts/   # pure types, JSON schema, parsers; no Cordis runtime. Authority for worker model, DAG, aggregate, path grammar, and bounds
  dsh-isolated-workspace/     # v0.4a package: manifest, isolated copies, diff, ownership check, transactional integration; consumed via injected seam
  dsh-orchestrator/           # gains task DAG, independence/ownership validation, parallel fan-out, aggregation
```

dsh-scheduling-contracts already defines CapabilityRequestV1, RouteDecisionV1, ScheduleDecisionV1, BudgetViewV1, ScheduleFeedbackV1, and ScheduleSelectedV1. v0.4 widens SchedulingConstraintsV1.maxWorkers and BudgetViewV1 bounds, adds the Task DAG, ParallelAggregateV1, ParallelVerificationPolicyV1, and the authoritative path grammar/types/bounds, and keeps the no-Cordis boundary. dsh-isolated-workspace imports grammar and bounds from scheduling contracts (single source, no cycle; scheduling-contracts never depends on isolated-workspace).

dsh-orchestrator adds a deterministic pure dag.ts module (DAG parsing/validation, cycle rejection, level/topological ordering, independence check, disjoint ownership validation) and extends the worker path so the parallel fan-out admits and runs N bounded workers with per-worker route selection, consumes the v0.4a isolation seam for ownership enforcement, aggregates normalized Handoffs into a ParallelAggregateV1, and runs integrated-result verification. Root route selection remains under the existing Adaptive Scheduler seam.

The execution flow:

```text
root task
  -> DAG submission API (deployment-controlled; validated test overlay or trusted code supplies a TaskDagV1)
  -> parseTaskDagV1 (strict, bounded) + validateTaskDagV1 (semantic): acyclic, disjoint ownership, bounded nodes/levels/width, subagentMaxDepth 1
  -> per-ready-level: v0.4a seam prepareLevel (isolated copies + immutable manifest)
  -> per-worker schedule: Adaptive Scheduler selects route per capability request (unchanged ScheduleDecisionV1)
  -> Orchestrator hard validation + BudgetController.admitFanout (atomic)
  -> parallel subagents.start('spawn') per worker in the shared working tree (same as Single Worker)
  -> per-worker Handoff normalization (self-reported changedFiles)
  -> v0.4a seam diffAndCheck per worker: actual diff vs declared writePaths
  -> v0.4a seam integrateAccepted (all-or-nothing) for ownership-valid workers
  -> aggregate ParallelAggregateV1 + integrated-result verification (parallelVerification policy)
  -> dsh-plugin durable events per worker and aggregate
```

## Contracts

### Constants (authoritative, in dsh-scheduling-contracts)

MAX_PARALLEL_WORKERS = 8 (max ready-level width; distinct from any configured default — config requires explicit maxWorkers); MAX_DAG_NODES = 16 (total nodes); MAX_DAG_LEVELS = 4; MAX_DAG_PATHS = 32 per node (readPaths and writePaths each); MAX_DAG_DEPS = 8 per node; MAX_AGGREGATE_ITEMS = 8 (node results); MAX_AGGREGATE_PAYLOAD_BYTES = 65536 (total UTF-8 payload); MAX_VERIFICATION_COMMANDS = 4 (per parallelVerification policy). All string/array bounds reuse the existing scheduling/handoff byte and item ceilings. Each constant has exact-bound and one-over-bound tests.

### Task DAG

```ts
interface TaskNodeV1 {
  readonly schemaVersion: 1
  readonly nodeId: string              // unique within the graph
  readonly objective: string
  readonly profile: CapabilityProfileV1
  readonly constraints: SchedulingConstraintsV1
  readonly readPaths: readonly string[]     // repository-relative read declarations (RepoFilePath | RepoDirectoryPrefix)
  readonly writePaths: readonly string[]    // repository-relative ownership declarations
  readonly dependsOn: readonly string[]     // nodeIds that must complete first
  readonly requiredTools: readonly string[]
}

interface TaskDagV1 {
  readonly schemaVersion: 1
  readonly rootTaskId: string
  readonly nodes: readonly TaskNodeV1[]
}
```

parseTaskDagV1(value) is strict and bounded: it throws TypeError for duplicate nodeIds, self-dependency, unknown dependency references, invalid path grammar, duplicate/overlapping declarations within one node, too many nodes/paths/deps, and over-limit string lengths. It returns a deep-frozen TaskDagV1.

### Independence, ownership, and depth

```ts
type DagValidationIssueV1 =
  | { code: 'cycle'; nodeId: string }
  | { code: 'missing-dependency'; nodeId: string; dependsOn: string }
  | { code: 'overlapping-access'; nodeA: string; nodeB: string; mode: 'ww' | 'wr' | 'rw' }
  | { code: 'write-outside-root'; nodeId: string; path: string }
  | { code: 'too-many-nodes'; count: number; limit: number }
  | { code: 'too-many-levels'; levelCount: number; limit: number }
  | { code: 'level-width-exceeded'; level: number; width: number; limit: number }

interface DagValidationV1 {
  readonly schemaVersion: 1
  readonly valid: boolean
  readonly issues: readonly DagValidationIssueV1[]   // deterministic order: by level, then nodeId, then issue code
  readonly levels: readonly (readonly string[])[]
  readonly levelCount: number                        // max dependency depth + 1; a graph with no edges has levelCount 1
}
```

Parser rejects structural violations (throw). validateTaskDagV1 returns semantic issues (never throws): cycle, missing dependency (already caught by parser, retained for completeness), same-level W/W + W/R + R/W overlaps (R/R allowed), write-outside-root, too-many-nodes, too-many-levels, level-width-exceeded. valid === true only when issues is empty. Dependency chains across levels are allowed; subagentMaxDepth = 1 means each spawned worker is a leaf that never recursively delegates — it is not a graph-depth limit.

### Path grammar

Authoritative in dsh-scheduling-contracts. RepoFilePath: canonical POSIX repository-relative path, no trailing slash. RepoDirectoryPrefix: ends in /. No glob metacharacters, no . or .., drive roots, empty segments, NULs, or backslash. Case-sensitive lexical containment: RepoDirectoryPrefix p/ contains path q when q starts with p/; RepoFilePath p contains only itself. No whole-repository sentinel; the deployment root scope is enforced by write-outside-root checks against the workspace root. Symlink traversal is a filesystem concern handled by the v0.4a seam at prepare/integration time (lstat/realpath under trusted root), never by the string parser. A normative containment examples table ships with the grammar.

### Widened worker model and budgets

SchedulingConstraintsV1.maxWorkers becomes 0..MAX_PARALLEL_WORKERS; BudgetViewV1 counters widen to the same bound. ScheduleDecisionV1 is unchanged: each worker keeps mode single-worker, workerCount 1, and its own route. Parallel execution is an Orchestrator-level execution mode driven by the validated DAG; the Scheduler never emits a batch decision and cannot change the DAG, write sets, or worker count. Existing single-worker/direct fixtures/tests remain valid.

Two distinct limits exist: maxParallelWorkers (max ready-level width) and the existing cumulative session worker budget (budgets.maxWorkers). DAG validation checks total node count (≤ cumulative budget) and max ready-level width (≤ maxParallelWorkers). Runtime admission adds an Orchestrator-only atomic admitFanout(workerCount): accounting rule — one delegate_worker plugin action per accepted DAG-level invocation (the root delegation), N cumulative worker admissions, and one targeted_verify action per verification command actually run by the parallelVerification policy. observed = current + requested for each counter; on overflow the rejection with the lower remaining capacity is reported first; exactly one durable budget-rejected event is emitted for an atomic fan-out failure. admitFanout commits all counters or none and is never exposed to the Scheduler. A preflight DAG/ownership failure consumes no budget. A runtime ownership violation (detected after the worker ran) consumes the admitted execution budget but blocks integration.

### ParallelAggregateV1

```ts
interface ParallelAggregateV1 {
  readonly schemaVersion: 1
  readonly fanoutId: string
  readonly scope: 'level' | 'dag'
  readonly levelId?: string
  readonly nodeResults: readonly {
    readonly nodeId: string
    readonly requestId: string
    readonly workerId?: string
    readonly status: 'completed' | 'blocked' | 'failed' | 'ownership-violation' | 'not-run'
    readonly handoff?: HandoffV1
  }[]     // unique nodeIds and requestIds; deterministic order
  readonly aggregateStatus: 'completed' | 'blocked' | 'failed' | 'verification-failed'
  readonly verification?: readonly VerificationEvidenceV1[]
  readonly ownershipViolations: readonly { readonly nodeId: string; readonly path: string }[]
  readonly integrationConflicts: readonly { readonly nodeId: string; readonly path: string; readonly reason: string }[]
  readonly projectedHandoff: HandoffV1    // explicit parent-visible projection, always present
}
```

Invariants enforced by parseParallelAggregateV1: nodeIds and requestIds unique; completed/blocked/failed nodes carry a handoff; not-run and ownership-violation nodes carry none; ownershipViolations exactly matches ownership-violation node results; integrationConflicts exactly matches integration-conflict results; scope 'level' has levelId and nodeResults bounded by MAX_PARALLEL_WORKERS; scope 'dag' has no levelId and nodeResults bounded by MAX_DAG_NODES (one aggregate after all levels). Status precedence (lowest wins for non-completed): verification-failed > failed > ownership-violation/integration-conflict > blocked > completed, where a single ownership-violation or integration-conflict forces non-completed. Verification is forbidden when nothing was integrated (no applied changes), and the aggregate then reports blocked with an explanatory summary. projectedHandoff is the deterministic HandoffV1 projection: status maps from aggregateStatus (completed → completed; blocked → blocked; verification-failed → failed with a [verification: failed] marker; failed → failed); summary concatenates accepted node summaries (bounded); changedFiles is the union of integrated applied changes (bounded); verification carries the integrated evidence; blockers carry ownership violations, integration conflicts, and blocked node summaries (bounded). MAX_AGGREGATE_ITEMS and MAX_AGGREGATE_PAYLOAD_BYTES cap nodeResults and total payload.

### Durable events and compatibility

Existing per-worker events (schedule-selected target=worker, worker-requested, worker-finished) remain byte-compatible v1 payloads for non-parallel runs. For parallel runs, v0.4 introduces one new v1 event dsh-plugin/parallel-finished whose payload is the bounded ParallelAggregateV1 projection (fanoutId, scope, per-worker requestIds/nodeIds/statuses, ownershipViolations, integrationConflicts, aggregateStatus, integrated verification outcome — no raw output, no transcript). Per-worker correlation for parallel runs is carried by extending worker-requested/worker-finished with optional fanoutId/nodeId fields that are part of the v1 type/parser/schema definitions (not additionalProperties-free rejection): old logs without the fields and new logs with them both parse; replay verifies both shapes. schedule-selected remains exactly as v0.3 (no field added). If extending the v1 payloads proves incompatible with any consumer, the fallback is a separate parallel-node-correlated event; the spec mandates both old-without-fields and new-with-fields replay coverage.

### ParallelVerificationPolicyV1

```ts
interface ParallelVerificationPolicyV1 {
  readonly schemaVersion: 1
  readonly commands: readonly {
    readonly name: string
    readonly args: readonly string[]
  }[]   // ordered; bounded by MAX_VERIFICATION_COMMANDS
}
```

parseParallelVerificationPolicyV1 validates that every command name exists in the deployment's configured verification.commands and that args obey the command's allowedArgs. Semantics: commands run in order after the level/dag integration, each consumes one targeted_verify plugin action (admitted via the existing controller before spawn), stop-on-first-failure maps the aggregate to verification-failed and emits verification-finished evidence per attempted command, zero commands means no integrated verification runs, cancellation aborts between commands and releases resources, and the policy is supplied by the test-only overlay or trusted deployment config (added to strict Orchestrator config parsing as an optional parallel block).

## Decision precedence

The Orchestrator owns DAG/ownership/aggregation decisions. Resource decisions keep the v0.3 scheduler precedence, applied per worker capability request; the Scheduler cannot change the DAG, write sets, or worker count beyond the validated DAG and budget. When the Scheduler is absent, the Profile fixed route is used per worker.

## Parallel execution model

- The DAG is submitted through a deployment-controlled entry point: a trusted-code API or a strict bounded parser over a model-authored proposal. v0.4 defines parseTaskDagV1 + validateTaskDagV1; the replay fixture supplies the DAG. No scheduling or budget action occurs before parsing and validation succeed.
- A fan-out runs only the ready nodes of one level; a level completes when every worker Handoff is normalized and recorded. subagentMaxDepth = 1; dependency levels are orchestrated by the root, never by recursive worker delegation.
- Each worker is a fresh subagents.start('spawn') child with subagentMaxDepth 1, frozen route, allow-only tool filter including targeted verification, running in the shared working tree (same execution model as Single Worker). The v0.4a seam provides the isolated copy for diff-checking, not the execution cwd.
- Ownership enforcement is diff-derived: after each worker completes, the v0.4a seam diffAndCheck compares the worker's actual changes in its isolated copy against declared writePaths; any out-of-ownership change marks the node ownership-violation and its changes are never integrated. Because execution is shared-tree, an already-written out-of-ownership mutation is detected but cannot be retroactively prevented; the shared tree is restored to baseline only for integrated paths via the transactional integration (v0.4a).
- Workers that fail, block, or produce invalid Handoffs do not abort healthy siblings; the aggregate reports each status. A node whose dependency failed/blocked/violated receives a synthetic not-run/blocked result and consumes no worker budget.
- Integrated-result verification runs once per scope under ParallelVerificationPolicyV1 (see contract), on the union of accepted worker integrations, never redundantly per worker.

## v0.4a isolation seam (consumed, not implemented)

v0.4 depends on the v0.4a dsh-isolated-workspace seam (implemented in v0.4a, faked in v0.4 keyless replay):

```ts
interface IsolatedWorkspaceSeam {
  prepareLevel(request: PrepareLevelRequestV1, signal: AbortSignal): Promise<PreparedLevelV1>
  diffAndCheck(levelHandle: LevelHandleV1, workerId: string, declaredWritePaths: readonly string[], signal: AbortSignal): Promise<OwnershipCheckV1>
  integrateAccepted(levelHandle: LevelHandleV1, workerIds: readonly string[], signal: AbortSignal): Promise<IntegrationResultV1>
  disposeLevel(levelHandle: LevelHandleV1): Promise<void>
}
```

PreparedLevelV1, OwnershipCheckV1, and IntegrationResultV1 are the bounded JSON contracts from v0.4a; path grammar and MAX_PARALLEL_WORKERS come from dsh-scheduling-contracts. In v0.4's keyless gate, a deterministic fake seam returns scripted isolated diffs and integration outcomes so DAG/aggregation/event/budget logic is tested without real filesystem/git operations. End-to-end physical diff/integration behavior is verified in v0.4a's own gate with real temporary filesystems.

## Safe degradation

- No Scheduler → per-worker Profile fixed route, deterministic and keyless.
- Scheduler invalid/out-of-bound decision → same validation failure and fallback policy as v0.3; never silently expands worker count or provider.
- v0.4a seam absent or failing → parallel fan-out fails closed before admission; no worker starts, no budget consumed, and the root degrades to the Single Worker path or reports the blocker under the existing handoff semantics.
- DAG parse/validation failure → reject fan-out before admission, record issue, no budget consumed.
- Ownership violation at runtime → execution budget remains consumed but integration is blocked and the node is marked ownership-violation; the shared tree is restored to baseline for any partially integrated paths (v0.4a transactional rollback).
- Provider auth/quota/rate-limit errors never trigger silent paid fallback.
- run-started keeps actual-route semantics.

## Evaluation and error handling

Keyless replay covers:

- DAG parser rejections (duplicate node, self-dependency, unknown dep, bad path, over-limit) and validator semantic issues (cycle, W/W/W/R/R/W overlap, write-outside-root, too-many-nodes/levels, level-width-exceeded) with deterministic issue ordering.
- Parallel fan-out admission: N workers within bound, atomic admitFanout rollback on partial failure with exactly one budget-rejected event, no child start before admission commits.
- Per-worker route selection (scheduler-present and profile-fallback).
- Per-worker Handoff normalization and ownership result from the v0.4a seam fake (diff-derived check vs declared writePaths).
- ParallelAggregateV1 construction, invariant enforcement, status precedence, and Handoff projection.
- Integrated-result verification under ParallelVerificationPolicyV1 (ordering, action accounting, stop-on-first-failure, verification-finished evidence, zero-command and nothing-integrated cases).
- Event provenance: per-worker schedule-selected/worker-requested/worker-finished (both with and without optional correlation fields) plus one aggregate parallel-finished; ordering and bounded payloads.
- Profile-fallback, invalid-decision, quota/timeout/cooldown, escalation, Direct actual-route, and read-only budget snapshot regressions remain green.

Missing optional services, invalid decisions, quota failures, and unknown provider/model values fail closed or degrade deterministically without provider access. Every timeout/cancellation path releases owned resources (including v0.4a workspaces via disposeLevel). The provider smoke command remains the exact keyless DISABLED check.

## Acceptance criteria

1. parseTaskDagV1/validateTaskDagV1 are pure, deterministic, bounded, keyless, and reject every listed condition before admission with deterministic ordering.
2. Parallel fan-out runs N bounded workers with per-worker route selection, atomic admitFanout (defined accounting, one rejection event), and no child start before admission commits.
3. Per-worker durable events carry optional correlation fields that parse in both old-without and new-with shapes; one aggregate parallel-finished event carries bounded provenance and integrated verification outcome.
4. Ownership violations are diff-derived via the v0.4a seam and never integrated; preflight DAG/ownership failures consume no budget; runtime violations consume execution budget but block integration and roll back partial integration.
5. A node whose dependencies failed/blocked/violated receives a synthetic not-run/blocked result and consumes no worker budget.
6. ParallelAggregateV1 invariants, status precedence, and projectedHandoff are deterministic and tested; verification is forbidden when nothing was integrated.
7. Direct, Single Worker, Handoff, budget, targeted verification, canonical events, Adaptive Scheduler, and keyless DISABLED smoke semantics remain intact.
8. profiles/v0.1 remains byte-for-byte unchanged; no v0.4 profile is added; the parallel path is validated by a loader-convention-compatible test-only overlay over the v0.3-adaptive profile with the v0.4a seam fake.
9. A named test:v0.4 gate (scheduling contracts + DAG/parser + Orchestrator parallel + loader/profile + tests/replay) plus typecheck, build, provider-disabled check, and git diff --check all pass.
