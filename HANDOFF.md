# Handoff

## Goal

Define a DSH-based personal Coding Agent plugin architecture that is ChatGPT/Codex-first, context-efficient, selectively multi-agent, and evidence-driven; establish a reusable Direnv + Home Manager DeepSeek Harness development environment for that work.

## Current Status

`README.md` records the full architecture baseline: lifecycle, component boundaries, data contracts, scheduling rules, prompt/cache behavior, code intelligence, memory, verification, telemetry, safety, a three-tier plugin reuse analysis, configuration, v0.1-v0.6 roadmap, measurable hypotheses, and the repository/package/plugin boundary strategy. v0.2a, v0.2b, and v0.2c are implemented on `main`; README marks the repository-defined keyless v0.2 scope complete while preserving the explicit absence of provider, network-isolation, and real coding-task acceptance. The project remains one pnpm monorepo through v0.6 while runtime capabilities evolve from the current Orchestrator and Code Intelligence plugins to four primary plugins (adding Adaptive Scheduler in v0.3 and Telemetry in v0.5), with Verification as a conditional fifth plugin only after independent consumers, permissions, or execution backends exist.

The repository now also provides a Nix Flake with a Node.js 24 development shell, a reusable `homeManagerModules.deepseek-harness-dev` module that only enables `direnv` and `nix-direnv`, and an `.envrc` containing only `use flake`. The shell supplies a `dsh-pnpm-wrapper` that invokes Node.js 24's `corepack pnpm`, takes PATH precedence over unrelated pnpm binaries, and preserves the upstream `packageManager` selection without writing shims into the Nix store. It also supplies `dsh-web`, which locates the repository-local Harness checkout and applies the required Nix Node compatibility launch automatically. The shell resolves `DSH_HOME` by walking upward for the DS-Plugins marker pair, so an independently cloned nested Harness Git checkout still uses the repository-local `.dsh`. `.gitignore` excludes direnv cache, that local state, and the upstream checkout. Harness remains a source-run dependency, not a global npm or Nix installation.

## Key Decisions

- Extend DSH through plugins; do not fork its agent loop.
- Treat model compatibility as higher priority than prompt-cache reuse.
- Let the Orchestrator request capabilities and let a scheduler select `provider + model + prompt profile + reasoning effort`.
- Delegate only when the expected benefit covers token and latency cost.
- Require evaluation before promoting prompt, routing, or policy changes.
- Keep a single pnpm monorepo through v0.6: packages, runtime plugins, and Git repositories are different boundaries. Maintain Orchestrator and Code Intelligence as the current plugins, add Adaptive Scheduler in v0.3 and Telemetry in v0.5, and split Verification only when independent consumers, permissions, or backends justify it. Keep contracts, context cache, eval, failure mining, and promotion governance as libraries/offline workflows rather than runtime plugins.
- Do not create one repository per plugin. Consider a Git split only for stable public contracts plus a real ownership, licensing/publicity, multi-host distribution, supply-chain audit, or irreducible CI boundary; if needed, prefer at most the product domains `agent-core`, `code-intelligence`, and `observability`.
